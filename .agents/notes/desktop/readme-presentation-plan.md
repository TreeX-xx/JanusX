## Janus 顶部形象

本节保留首轮胶囊方案的探索依据。用户后续明确 Janus 保留原圆角胶囊，仅字标采用像素块风格，现已按 [头图决策](./readme-janus-header.md) 实施；以下候选保留作对照，胶囊比例仍沿用，当前字标与动画以头图决策为准。

取样来源是 `JanusIsland`、眼睛组件及主题 CSS 的实际最终样式，不照搬可能过时的注释。保留长胶囊、成对眼睛、真实眼距和小幅表情；不沿用现在的方形像素头与求 Star 小剧场。

三种可审方向：A「静态胶囊 + 字标」，最清楚、兼容最好；B「胶囊轻眨眼 + 字标」（推荐），约 6–8 秒一循环，绝大部分时间静止；C「胶囊展开一条通知再收回」，产品感更强，但会与正文演示争夺注意。首轮先出三张静态候选，不先批量做动画。

推荐构图约 760×160：胶囊与 JanusX 字标并列，简短副句放在 Markdown 正文而非图内。石板色版本采用真实纸面/墨线/墨眼；深色版本沿用真实深色胶囊，不额外发明霓虹色。可用 picture 根据 GitHub 明暗环境选头图，这与演示中的应用主题是两件事。

动效只做一次眨眼或小幅视线变化，状态环若使用须与产品真实状态一致。SVG 无动画时仍保留完整形象；支持 reduced-motion，必要时提供 PNG 后备。链接放 Markdown 外层，不能依赖 img 内 SVG 的按钮可以点击。验收同时看 320px 窄屏、GitHub 明暗背景及静止帧。

首版候选已按用户要求制作：[胶囊 SVG](https://github.com/TreeX-X/JanusX/blob/v0.9.3/wiki/assets/readme/janus-header-capsule.svg)、动态预览页 (`design/Janus-README-Capsule-Preview.html`; local, untracked)、[明暗背景预览图](https://github.com/TreeX-X/JanusX/blob/v0.9.3/wiki/assets/readme/janus-header-capsule-preview.png)。胶囊按软件 52×26、眼睛 8×10、眼距 3 的几何放大三倍，采用纸色墨线与朱红 X；8 秒循环内一次轻眨，减少动态时静止。字标随阅读背景适配，胶囊保持默认主题。XML 解析通过，Playwright 渲染并目视检查 1000px 与 375px 页面；尚未在 GitHub 线上验证。胶囊形象已获用户认可；随后已将胶囊与重新设计的 Star 邀请动画接入 README，实际实现见 readme-janus-header.md。上述胶囊独立预览保留作对照，其余功能演示改版仍待实施。

## 演示素材与分镜清单

统一使用一个本地演示项目 `Atlas`（任务看板示例），包含 `main`、`feature/search`、本地预览页、少量源文件、项目 Notes 与示例会话。内容形成联系：并行开发搜索 → 看结构约定 → 查看消耗 → 找回相关会话 → 查看产物。各片仍从独立 fixture 启动，单独可重录，不依赖上一片执行结果。另准备 `Beacon` 验证切项目时工具保留。

选材原则是「结果完整、过程有重点」。GIF 至少完成一个用户目标，不只是打开面板；复杂流程允许 25–45 秒，明确分阶段。图片承担需要停下来读的布局、数据和集成状态。长等待可剪短并标注，不能跳过输入、确认与结果验证。末尾留 2–3 秒读结果。

### 对话、审核和数据的录制条件

Island、运行配置、蓝图维护分别使用真实对话入口，不能用一个聊天窗口替代全部能力。样本项目 scripts、源文件和 Note 相互对应；运行配置确实能启动本地演示服务。可扩展现有确定性模型保证复现，但必须驱动真实读取、写入、确认与审核发布链，素材说明标明脚本模型/示例数据，不作为模型智能或审核质量的实测证明。

B1/B2 共用故事、独立 fixture。B1 演示有源码依据的约定更新；B2 植入明确矛盾，让审核发现，再经修复对话和复审闭环。自动审核默认关闭且 N=5；仅在隔离环境设 N=1，片内注明「演示：每次提交检查」。先配置审核模型、启用并建立基准，再产生新提交。保存文件不等于 Git 触发，右侧普通聊天也不直接启动审核。

B2 保留提交、审核开始、建议出现、修复、复审结果五个证据点，长等待明确压缩。若 45 秒仍不可读，拆成同节相邻的「自动审核」与「对话修复和复审」两片，素材数随之增加，不以提速牺牲完整性。不改灯色/意见数量伪造成片，不承诺审核必然无漏报。

U 的终端遥测与账本使用一致的会话标识和请求样本；历史范围包含其他会话时，总额不应强行等于当前抽屉。分别验证精确值和汇总关系。缺数据的引擎不造数值，费用保留估算说明。CPA 与统计不暗示自动共享全部账号、额度和请求。会话主片展示继续原生对话确认并取消；不执行 Resume，不把它描述为文件恢复。

### 鼠标衔接与真实 UI 动画

当前 snapper 保留 lastMouse，但点击后只截点击帧、等待约 450ms 再截结果帧。用量数字和曲线在 260–420ms 动画，因此可能恰好跳过完整过渡；拖拽逐帧 screenshot 的实际耗时也不同于 manifest 的 40ms。这是要验证的采样风险，不是已复现结论。

实施先做 5 秒试片，对比连续录屏/帧流与当前截图序列。鼠标叠加使用同一时间轴，实际 UI 操作采用同一条路径；以 25fps/40ms 为 GIF 起点，动画期间连续采样，稳定定格可合并长延时。若截图循环无法稳定捕获真实过渡，改用支持真实 Electron 与原生子视图的连续捕获方案，经样片核验后再批量录制；不通过插帧制造不存在的界面状态。

运动初始建议：移动 250–650ms（随距离变化），目标悬停 180–300ms，拖拽 650–1100ms，落点停留 400–700ms，结果阅读 1.5–2.5s。点击提示细而短，拖拽保持按下态，松手不能像第二次点击。指针移至不遮挡数字/代码的安静区域后停留；无操作时不漂移。

循环不能直接从末尾指针跳回开头：可逆流程用真实动作恢复并回到相同停泊点；创建/修改等不可逆短片先保留结果，再用明确的短淡出/淡入重置画面，指针在静止处同步淡出，不跨屏瞬移。转场仅在真实应用帧之间做后期，不伪造操作或结果。

每次录制将 theme、背景、鼠标、尺寸、字幕样式写入 manifest；重合成默认遵循快照，换样式必须显式覆盖。单片不更换 palette。固定外底预留关键颜色，若保留渐变须测试量化色带；背景检测排除应用、字幕、指针和阴影，只比较确定静止区域。透明增量编码必须在解码后的完整画面验证，尤其循环第一帧的完整刷新。
