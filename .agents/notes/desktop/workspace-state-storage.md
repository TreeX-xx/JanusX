# 工作区私有状态迁出项目目录

## Problem

启动配置属于本机项目配置，命令日志属于应用私有状态；默认放在项目内会污染目录，并增加监听、同步、备份和工具扫描的附加开销。P2 将这两类数据接入 userData，已有旧数据需用户主动迁移；已退场的文件还原点在主动迁移时直接清除。P3 已将 JanusX Hook 资产及附加配置改为 userData 内的单次启动注入；旧 Hook 条目与残留目录仍待 P5 核对，不能将新写入路径切换解释为历史 `.janusX` 已全部退场。

实施由[工作区数据、读写与 Hook 生命周期总计划](../planning/workspace-data-lifecycle-plan.md)统一编排，后续由用户逐阶段调度；本篇保持存储和读写设计事实的归属。

文件还原点已退场：终端提交与 Agent 文件工具不再生成持久化快照，检查点 IPC 仅兼容拒绝；右侧 Island 继续独立捕获回合内存基线和显示差异。用户主动迁移时直接清除旧还原点，包括此前已迁入 userData 的副本；不再复制或按时间、数量保留，详见[会话检查点模块](../sessions/checkpoints/module.md)。启动配置仍参与表单、运行器、项目检测与 worktree 配置继承。

## 当前读写与清理事实

文件工具及共享 I/O 位于 `@janus-agent/agent-core`，命令执行位于 `@janus-agent/node-hosts`，源依赖来自相邻 `janus-agentX` 仓库。桌面已停止检查点初始化、捕获和恢复调用；旧引擎导出仅作兼容。Agent 文件工具保留路径、审批、哈希与提交复核、原子替换、取消、队列和本次 diffPreview，不再为每次修改扫描全工作区快照。

同步命令流式写日志并使用背压，桌面后台命令退出时分块保存尾部 1000 行，启动配置只在保存时写入。列表不计算占用；手动统计仅枚举私有文件及 stat，不读正文。维护不扫描源码、不读日志正文，也不再扫描旧快照元数据或计算其年龄。显式清除旧快照只核实路径、文件名与链接边界，不读正文、哈希或重建索引。P1 的代表性采样归最小读写方案；目录迁移和自动化测试不保证物理磁盘占用百分比。

P4 按 30 天维护已迁入的历史日志及解除最后关联的数据，旧快照取消原年龄和数量策略。工作区移除先停止其终端、带 workspaceId 的运行任务和 Office 监听，仅移除侧栏记录；到期或显式永久清除才删除已验证的 userData 私有目录。旧 `.janusX` 只通过 P2 主动迁移清理，P4 不递归删除它。仍未完成 P2 源清理的数据暂不自动老化，避免目标副本变化阻断回执核验。

## Decision

由主进程在当前有效 `app.getPath('userData')` 下管理 `janusx/workspace-state/<storageId>/`，保存版本化 manifest、launch.json 和 logs；checkpoints 路径仅为旧数据兼容清除保留。新工作区直接使用新存储，不创建项目根 `.janusX`；已有旧数据的工作区在用户主动迁移前继续使用旧存储，成功后单向切换。读取不存在的数据不创建目录，首次真实写入才落盘。只迁移 JanusX 私有配置和日志；源文件、Git、工程 Notes、项目依赖和构建产物继续由项目及其工具拥有。团队共享运行配置通过显式导入／导出提供，现有配置继承语义保留。

storageId 是随机 UUID，不使用显示名称或单纯路径哈希。P2 的本地目录关联以 realpath 和 dev／ino／birthtimeNs 核实，同路径被替换得到新身份，同目录重复导入复用经验证的关联，不同 worktree 和 profile 隔离。无注册记录的工具调用也通过统一解析器持久关联。远程工作区在迁移页面明确标为不支持，不把远程路径当本地目录访问；远程私有状态迁移留待对应运行环境实现。

显示名称变化不改变存储身份。P4 提供显式重新定位、移除后恢复关联及过期清理，不从名称猜测目录。路径暂时不可访问只标记不可用，不开始移除计时；同路径目录身份改变时分离旧数据与新项目，不能静默继承。

## 生命周期与清理（P4 已实施）

用户授权先移除快照再实施 P4，并明确后续迁移不再保留还原点。本版日志和移除后数据共用 30 天窗口；旧快照仅通过主动迁移或分类清除直接删除，不再有 30 天、最多 40 个、至少 5 个策略。复用 P1 常量，不增加容量预算、轮询周期、重试次数或可调阈值面板。

持久关联从工作区记录推导，不额外维护一份易失真的引用计数；无侧栏记录但经统一解析器登记的工具存储不自动判为孤儿。从侧栏移除工作区先停止关联任务、释放读写资源，再解除关联；最后一个关联解除时仅写入一次 detachedAt 并进入恢复期，重新导入可恢复尚未清理的关联。离线、权限变化、移动盘未挂载只标记不可用，不启动解除关联计时。显式永久清除只删除已核实身份的应用私有数据，不删除项目文件或递归删除旧 `.janusX`。

终端、活动命令、日志读取、Agent 文件修改及启动配置读写持有使用保护，父目录清理同时检查子目录使用者。清理期间阻止新使用者，配置调用仍保留同工作区队列顺序。删除前向 registry 和 manifest 持久化 purging；即使中断发生在 manifest 删除后，也能根据 registry 续作并阻止半删除数据重新挂接。复用当前 profile 单实例入口，不新增跨进程租约；独立 CLI 或旧应用需先退出。

关联中的启动配置不按年龄过期。旧快照清除覆盖 checkpoints 顶层 JSON（含索引）、blobs 中的 40 位小写十六进制文件及对应旧迁移临时文件；不解析快照正文，因此损坏 JSON 或缺少引用块不阻断清除。删除前先验证整个快照树，未知文件、未知子目录和链接会保留并报告，不越界跟随链接。旧快照不是原生 CLI 会话记录或完整项目备份，清除会删除历史内容，不删除项目源码、聊天或 Island 当前差异。文件还原点功能保持退场。

日志按最后写入的 mtime 及迁移保留期取较晚时间，再加 30 天；日志活动期间有使用保护。最后一个记录解除时持久化 detachedAt，30 天后清除整份私有数据，重启不刷新。共享 Hook 文件保持固定集合，旧版本及全局残留归 P5。时间策略不保证磁盘字节总量有硬上限，确有实测需求再扩展。

维护只保留一个去重任务，复用 P1 的 32 文件／批、64 个等待任务、后台批间 20ms。启动、私有写入、关联变化、终端关闭和用户检查触发维护；仅对确有占用延期的工作监听使用保护释放。每份存储在内存记住下次检查时间，到期前不重复扫描日志；旧快照不参与定时扫描。运行期间只预约最近一次到期，平台定时器超长时间分段不改变到期日期。后台任务脱离调用者队列上下文，避免从前台配置事务启动时意外继承前台优先级。前台其他目录可在批次边界插入；记录变更、恢复关联与清理共用事务避免半删除重挂。失败保留原因，下次相关事件或重启重试。普通升级不刷新时间，P2 首次成功主动迁移的一次起算例外保持。

### 重新定位交互

侧栏对无法访问的工作区轻量标记“文件夹不可用”，不在启动时逐个弹窗。用户打开该工作区时，展示局部提示：“找不到原文件夹，可能已移动或暂时不可用。”显示原路径，提供“选择文件夹”和“重新检查”，允许关闭提示。工作区菜单及设置对应条目保留“重新定位”入口，支持用户主动处理改名或移动；只改显示名称无需重新定位。

“选择文件夹”使用系统目录选择器，取消不改变关联；选中后核实目录身份。同一目录移动或改名后仍能核实时更新路径并复用 storageId，userData 数据不复制、不重算保留期；路径变更与资源重新绑定在无活动任务时提交，有活动任务则提示先停止并保留当前状态。不能核实同一身份（包括部分跨盘复制）时，明确说明无法确认是原文件夹，提供“作为新工作区添加”，不静默继承旧检查点；旧关联仍可在数据管理中处理。不扫描整盘寻找目录，也不以同名或 Git remote 相同替代身份验证。

### 设置界面

复用“设置 → 通用 → 数据管理”，与 P2 的旧数据迁移入口并列呈现。采用克制层级、轻分隔线、主题变量和次级详情，保持用户要求的 Codex UI 简约方向；实际组件已在 Chromium 明暗主题、480px 宽度检查，无横向溢出，展开详情支持键盘。

列表展示名称、路径及已关联／不可用／待清理／清理失败状态；待清理项展示实际到期日期，策略说明明确日志和解除关联数据保留 30 天，旧还原点直接清除、不再迁移或按时间数量保留。按需展开路径与错误详情，完整路径可复制；占用由“计算占用”主动触发，打开设置不遍历目录统计大小。提供重新定位、恢复关联、分类清理及永久清除入口；清理执行前说明对象、历史内容将删除以及项目源码不受影响，仅实际不可撤销操作需要确认。默认呈现固定策略说明，不为本轮方向额外增加一组可调阈值设置。

## 最小读写门控（P1 已实施）

用户要求减少设计复杂度及难维护阈值。以[最小读写方案](../planning/workspace-data-contract-baseline.md)为实施依据：一个宿主队列串行执行重型读写批次，同目录变更保持顺序；初始化和相同查询共享执行，列表只读元数据；扫描、日志和空闲清理分批处理，关闭时取消无用请求。首版采用 32 文件／批、全局最多等待 64 个任务、后台全量扫描批间休息 20ms，沿用已有大小保护，增量扫描后置。

撤下多层速率预算、令牌桶、自适应压力降速、复杂优先级及旧复杂实验阈值。先消除多终端扫描叠加、查询风暴、大日志集中写和重复 GC，再用代表场景验证；后台固定休息不延迟显式写前保护和恢复，实测不足再按证据调整。

P1 当时的检查点写前捕获契约已被用户授权的快照退场取代；现行 Agent 文件工具保留冲突、路径和提交复核，不再提供历史恢复。Island 的回合基线依然独立且不能以部分捕获冒充完整差异。P2 迁移与 P4 清理复用同一通道和三个常量。自动化结果及限制见最小读写方案和本篇。

## 升级、降级与迁移

应用版本号与数据格式版本、清理策略版本分离。正常覆盖升级复用稳定的 userData 和 storageId，不按应用版本创建新目录、不重置最后使用时间或恢复期。沿用[应用 profile](./application-profile.md)的开发版、安装版、免安装版隔离；切换发行渠道或显式 user-data-dir 是选择其他 profile，不能自动合并或把另一个 profile 当孤儿数据删除。

P2 的 manifest 使用 schema 1，记录 storageId、当前关联路径、retentionStartedAt 及迁移回执；后续清理策略字段由 P4 引入，不预填未实施的策略。未知新格式或损坏 manifest 保留并报告。升级只执行明确的格式迁移，不自动重置时间。收紧清理策略需明确过渡规则，不能在升级首次启动时意外批量删除历史；不能承诺旧版应用或未来所有版本天然理解新格式。

旧 `.janusX` 迁移由用户主动触发，仅复制启动配置和日志：在旧写入已停止后复制、校验、记录回执并切换读取，然后删除已验证的旧源文件，并直接清除来源及目标的 checkpoints 树。还原点不复制、不读取正文或校验块引用；只有还原点的工作区也能执行。旧回执中的检查点条目仍可加载，但不再比较其源／目标哈希，而直接清除已知快照文件。已完成迁移但仍有来源或 userData 还原点时重新显示待清理，沿用同一操作重试且不刷新时间。未知文件和尚未迁移的 Hook 资产保留，只有空的 `.janusX` 才移除。复制或校验失败保留原数据（包括还原点）且不覆盖目标新数据；切换后删除失败显示清理未完成，后续只重试清理，不重复导入或退回旧存储。批量选择按工作区逐个排队，单项失败不阻断其他项。普通启动不单独清除关联中旧快照；解除关联到期的整份数据清除仍适用。

用户确认主动迁移时，迁入日志的时间保留期从首次成功切换时间重新起算一次，单独持久化 retentionStartedAt。失败、重试、旧文件清理重试和普通版本升级均不刷新这个起点；已退场的还原点直接删除，不参与保留期起算。此项是主动迁移的明确例外，替代之前“迁移也不重置保留期”的设计。

迁移入口只列出当前 profile 已登记目录，不扫描整盘。复制保留原件，因此临时需要容纳一份迁入数据；磁盘不足作为可重试失败报告，未引入容量预算系统。目标同名文件内容不同即中止，不覆盖。Agent 使用 command.read-log 按当前 workspaceId 和文件名 logId 分页读取，默认 16 KiB、最多 64 KiB，拒绝路径穿越和跨工作区读取，不授予任意 userData 读取权限。宿主注入接口在 janus-agentX 源码维护；独立 CLI 未注入时保持旧路径，不直接修改 node_modules。

## 升级提示与设置入口（P2 已实施）

常驻入口放在“设置 → 通用 → 数据管理”区块，条目名为“旧工作区数据迁移”。直接展示已登记工作区的待迁移、已迁移、离线／无法检查、失败及旧文件待清理状态，不新增一级分类或中间管理按钮。可选择单个或批量工作区，再点击“迁移并清理旧文件”执行。执行前说明会迁移哪些私有数据、校验后清除对应旧文件，并重新起算迁入数据的时间保留期；未知文件可能使 `.janusX` 继续保留。

首次运行支持该能力的升级版本时，应用界面就绪后，对已登记且可访问工作区只做旧存储存在性检查，走 P1 队列，不统计完整目录大小或扫描源码。发现旧数据才显示一次可关闭提示，明确声明仅迁移启动配置和命令日志、当前 profile 的实际目标绝对路径，以及校验切换后清除旧文件并直接删除来源和已迁入 userData 的还原点。提供“前往迁移”和“稍后处理”；前者直接定位上述设置区块，不执行迁移，后者关闭提示。提示不阻断正常使用、不自动打开设置、不自动复制或删除数据。新安装且没有旧数据的用户不显示提示。

设置迁移页在执行按钮之前持续展示每个工作区的实际来源目录、实际目标目录及本次找到的处理类别，映射为 `.janusX/janusX.launch.json` → `launch.json`、`checkpoints/` → 直接清除（不迁移）、`.janusX/logs/` → `logs/`，缺失类别标注“未发现”，不暗示会完整搬走整个 `.janusX`。目标根路径由当前有效 userData 动态解析，不写死 `%APPDATA%/JanusX`，具体工作区目标包含其 storageId。完整路径可换行并可复制，不能只保留截断文本。批量迁移逐项展示对应来源和目标；前往迁移前可先展示目标根目录，具体 storageId 路径在解析后、执行前呈现。页面同时说明迁入数据的时间保留期在首次成功切换时重新起算一次，普通升级和重试不再次重置。此处只展示路径和范围，不为展示目录而创建实际数据目录。

提示已展示状态按当前 profile 和迁移功能标识持久化，不按每个应用版本或每次启动重新提醒。关闭提示后仍可从设置进入；没有已知待迁移项时不消耗提示展示状态，后续发现旧数据时可提示一次。离线工作区不当成没有数据或已经完成，用户重新连接后在设置重新检查。所有已知项目迁完后入口仍保留，显示“暂无待迁移工作区”，并提供“重新检查”；轻量检查与迁移进度独立，打开设置不自动迁移。

## Alternatives considered

保留根目录布局实现成本最低，但不满足用户的目录边界要求；按路径哈希建目录简单，却会在移动后遗留孤儿状态。稳定身份与应用数据集中管理增加注册、重新定位、清理和跨版本迁移成本，但使改名、移除及占用治理具备统一语义。若后续需要跨电脑携带或共享状态，再设计显式导出，不恢复默认根目录存储。

## Consequences

P2 与 P4 的本地实现已落地。重新定位只确认同一文件系统目录身份，跨盘复制无法确认时显式作为新工作区添加。快照退场接受失去普通文件工具历史恢复的代价，不另建备份系统；没有跨进程锁或字节配额。真实升级安装包、慢盘、长期运行及多进程兼容仍归 P6，不能用本地自动化代替。

## P2 实现与验收
