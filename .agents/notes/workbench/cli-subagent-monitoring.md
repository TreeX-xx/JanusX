# 当前终端的多智能体监控与右侧 Island 详情

## Problem

用户需要跟随当前选中终端显示智能体状态：单智能体显示主智能体，多智能体展示主子关系，点击任意智能体查看当前任务与执行内容。2026-10-29 明确详情使用右侧 Island，并关注移动、加载和显示效果。

后续计划开发类似 Codex 界面的非 CLI 对话框版本，并保留启动各种终端的能力。CLI 本身已有子智能体查看与交互入口，独立监控的增量主要是降低查看与判断成本；若先完整实现监控，再为对话框实现同类展示，容易重复投入。当前尚无用户使用数据证明完整监控应优先开发。

当前 `JanusIslandExpandedShell` 已按 `activeTerminalId` 筛选运行记录，但列表平铺、`slice(0, 6)` 截断，点击只切换身份预览。`SubAgentRun`、registry/store 已有父子关系与事件链路；CLI 内部子智能体发现及正文接口尚未接入。右侧 `JanusAuxiliaryIsland`、共享布局和动效已存在，但宿主目前只在 roundtable 视图启用辅助面；已有 `runtime-detail` 类型不代表监控详情已经接通。

## Decision

2026-10-29 确认开发顺序：先开发非 CLI 对话框版本，再在真实对话场景中开发多智能体展示，最后将已验证的展示能力复用到 CLI 模式的监控界面。完整 CLI 监控暂缓，保留以下右侧 Island 设计作为后续接入目标；对话框版本的完整范围与排期尚未定义。本次只记录决策，相关能力仍未实现。

### 共用展示与接入边界

多智能体视图应可嵌入对话框与监控宿主，共用主子关系、任务摘要、状态、活动记录与结果展示，以及选择、折叠、增量更新和阅读位置保持。两种模式通过各自的数据适配接入统一契约，避免公共组件绑定对话框运行逻辑或 CLI 文件格式。

```text
对话框模式的运行事件 ─┐
                    ├→ 统一智能体数据 → 列表／树／详情 → 对话框或监控宿主
CLI 会话记录适配 ────┘
```

统一契约至少表达智能体与会话身份、父子关系、任务摘要、状态及其证据来源、最后活动和内容引用。仅在掌握运行链路时，对话框模式才能直接使用运行事件；外部 CLI 模式仍需独立适配会话记录，承担格式变化、写盘延迟、记录缺失与未知状态的处理。展示组件复用不代表 CLI 数据接入自动完成，也不保证两端具有相同的实时性与完整性。

发送消息、停止任务等操作按数据源实际能力提供；公共视图与宿主布局、终端定位及控制操作分离，CLI 仅有只读记录时不显示不可执行的控制。公共部分先由真实对话场景形成，再尽早接入一个 CLI 验证复用边界，随后按需求扩展其它引擎，避免过早建立覆盖所有 CLI 的抽象。

### CLI 接入目标：监控与详情交互

主监控面负责当前终端摘要、主身份与智能体树。点击主行或子行统一打开主 Island 右侧的辅助 Island；左侧身份区可以同步选择，但任务正文由辅助面承载。不创建中央 pane 标签或独立窗口。终端边缘的 `TurnChangeIsland` 仍负责回合历史，本方案的“右侧 Island”指主 Island 的右侧辅助面。

- 顶部显示终端、CLI、当前会话与各状态数量。无终端、普通 shell、未绑定会话、尚无子智能体分别说明，不伪造运行项。
- 主行固定可访问，按 `parentRunId` 缩进组树并提供独立折叠按钮；活跃分支优先，完成分支折叠保留。超过默认数量通过滚动或“展开其余 N 个”访问，不静默截断。
- 点击行立即选中并打开详情，再点当前行保持打开，不重置滚动或重复请求。通过关闭按钮或 Esc 收起详情，焦点返回发起行；关闭不停止任务。
- 详情显示名字、角色、状态、父子路径、当前任务、当前活动、执行记录与结果。主任务取当前用户回合及有效补充，子任务取派发指令及后续更新，昵称不能替代任务。
- 点击另一智能体，在同一辅助面切换内容；排序、状态变化和新增子智能体不抢选择或焦点。仅确实有独立终端的 run 提供定位终端动作。
- 切换终端或其绑定的 CLI 会话时立即失效旧请求、收起详情，监控恢复新会话主智能体；用户再次点击后打开新详情。离开 monitor 或收起主 Island 时关闭监控详情。
- 宿主同一时间只呈现一个右侧辅助面，与圆桌／结果等模块统一切换，不叠加多个面板。

```text
主 Island / 监控                         右侧辅助 Island
当前终端 · 主状态 · 子智能体数量           主智能体 › worker · 执行中      关闭
主智能体                 执行中           当前任务：接入监控数据……
  ├─ explorer            已完成           当前活动：读取会话解析代码
  ├─ worker              执行中 ←         执行记录：指令 / 工具调用 / 输出
  └─ reviewer            等待输入         结果：尚未完成
```

### 移动、加载与显示效果

“移动”首先按面板位移与动效连续性设计；窄窗口回退同时记录，不据此宣称移动客户端已支持。

| 场景 | 设计表现 |
|---|---|
| 首次点击 | 行立即选中；先绘制稳定尺寸外壳、标题与状态。复用现有 220ms、右侧偏移 8px 的淡入／回位，主面按共享布局同步让位，不等待正文返回才展开。 |
| 首次读取 | 超过约 150ms 再显示静态骨架与“正在读取执行记录”；快速返回直接展示，不强制最短加载时间，不显示虚构百分比。 |
| 正文就绪 | 只让正文短淡入，参考现有约 180ms reveal；外壳不重挂载、不重复移入，不随文字长度改变高度。 |
| 快速 A→B→C | 标题和选中态即时跟随目标；有目标缓存则展示并标记刷新，否则显示目标加载态。不能将 A 正文留在 B 标题下；仅接受当前会话及最新选择的响应。 |
| 后台刷新 | 已有正文保留，仅轻量显示更新提示和同步时间；追加内容不重播面板或历史消息入场，失败保留已读内容并提供重试。 |
| 阅读历史 | 贴底时跟随新消息；向上阅读时保持位置，提示“新增 N 条／回到底部”。加载更早记录保持阅读锚点。 |
| 收起／反向重开 | 复用 presence，退出内容保留至约 220ms 结束，并立即禁用交互；重开取消旧清理。关闭后晚到响应不能重新弹开详情。 |
| 窗口变化 | 复用 parallel、compact、stacked、focus 与防抖动阈值，依空间从右侧并列退为紧凑、上下、单面聚焦；聚焦态明确提供返回监控，保留选择与阅读位置。 |
| 减少动态效果 | 遵循 `prefers-reduced-motion`，取消位移与分段入场，保留静态加载文字和即时状态变化。 |

几何只由共享布局求解，正文加载不能推动主面反复移动。复用现有前后几何差过渡，不把动画中间尺寸重新输入求解；连续 resize 沿用即时适配，避免叠加动画。加载延迟和正文淡入时序在真实交互验证后微调。

辅助面具有可访问标题、`aria-busy` 与轻量状态播报，打开后焦点进入标题／关闭操作区，自动更新不抢焦点。Esc 优先关闭辅助面并消费事件，避免同时关闭主 Island。读取失败、尚未落盘、引擎不支持、部分记录分别说明。宽窄视口、短窗口与主题均需验证。

### 数据来源与归属

子智能体检测被动只读各 CLI 自己的 session 持久化，不新增 hook 装订、不修改 CLI 配置；既有主智能体 hook 状态链路继续复用。历史样本见[子智能体会话结构实测](../sessions/records/session-subagent-structures.md)，当前版本仍需补验。

| 引擎 | 适配来源 |
|---|---|
| Codex | 独立 rollout、显式父线程 ID、派发调用与正文；跳过复制的父线程历史，防止误当子智能体当前活动。 |
| Claude Code | 子 JSONL、agentId 与主派发记录，兼容旧 sidechain；以已验证 ID 归属，不能按连续块或时间邻近猜父子。 |
| OpenCode | SQLite 父子会话关系与 message/part；具体字段及状态证据按当前版本验证。 |
| JanusX 自编排 | 既有 registry 登记，与 CLI 内部派发共用树和详情契约。 |
| pi / dsh | 子智能体能力暂不覆盖，保留已支持的主状态并明确详情限制。 |

必须绑定“终端 → 当前 provider 会话 ID → 显式父子会话链”，同项目两个同 CLI 终端不得串数据。稳定 ID 包含引擎和会话身份，不能只以 `terminal:{id}` 缓存历次会话内容。父记录晚到先暂存子记录，链补全再展示；缺失关系或循环不得猜挂最近终端。

适配器输出统一记录，经投影器写入 registry，再由 IPC/store 增量更新；UI 无 CLI 格式分支。树字段可复用，但完整需求需补会话身份、任务／内容引用、状态证据、最后活动与正文接口，不再承诺模型及 IPC 零改动。被动采集增加明确 transcript 来源语义，不能伪装为 `source: 'hook'`。

### 状态、任务与内容读取

状态需要区分 queued、running、waiting-approval、waiting-input、idle、done、failed、cancelled、unknown；同步更新枚举、排序、标签、终态保留和消费者。无新输出不等于完成，一条 assistant 回复不等于结束；父等待子时保留父状态及等待原因，子状态独立更新。未知状态显示最近活动／同步时间，不能扫描到旧文件就默认执行中。进程退出、会话切换和异常残留需有中断／未知处理。

任务取当前有效指令及补充，活动取最近公开工具调用或消息，结果取有结束证据的输出。以本地正常写盘后约 1–3 秒可见为验证目标，实际受 CLI 写盘影响，不作毫秒级实时承诺。

增加按 `runId` 读取详情的统一 IPC，主进程验证会话和归属，只解析登记的内容引用，不接受 renderer 传任意文件路径。任务元信息单独读取／缓存，不只靠尾读恢复初始任务；正文有界分页、游标增量读取，标记缺页与部分记录，不跨缺口拼接虚构完整内容。复用 transcript-kernel、reader/excerpt，64KB 尾读仅为片段策略。

只对选中详情持续刷新，关闭释放正文订阅；全局身份与状态采集保持自身生命周期。缓存及请求身份至少包含工作区、终端会话、引擎、runId 和内容修订，并设置有界预算；换会话失效，响应带请求序号。展示落盘指令、公开回复、工具调用与结果，不承诺获得模型内部思考。

## Implementation shape（未实现）

1. 对话框基础：先做通非 CLI 对话框的单智能体交互，具体版本范围另行定义。
2. 多智能体展示：围绕真实对话任务实现列表／树、任务与状态、执行详情及阅读交互，形成可嵌入的公共视图与数据契约。
3. CLI 复用验证：紧接上一阶段选择一个 CLI，完成会话发现与绑定、显式父子关系、状态证据和正文读取适配，将同一公共视图嵌入监控宿主，验证两种数据来源与能力差异。
4. 按需扩展：在复用成立后增加其它 CLI 适配和脱敏真实 fixture，逐步完成下述监控验收。

CLI 接入阶段仍需补足会话身份、任务元信息、主／子详情 IPC、分页增量、缓存失效与异常残留处理；移除六条静默截断，让 monitor 接入宿主 `runtime-detail`，复用 JanusAuxiliaryIsland、共享布局与动效，并验证稳定加载、竞态保护、增量阅读和焦点返回。完整监控交付保留主／子内容查看与异常残留处理要求，不把三家适配全部完成作为首次复用验证的前置。嵌套派发对外宣称支持前补真实样本，不支持形态明确降级。

## Acceptance criteria（待实施验证）

以下保留完整 CLI 监控的交付目标，待对话框与公共多智能体视图形成后分阶段验证，不表示当前立即实施全部功能。复用验证还应证明两种来源使用同一公共视图，CLI 缺失状态与控制能力如实降级，公共组件不含 CLI 格式分支。

- 当前终端只显示当前会话主子智能体；同项目另一终端、历史会话与复制历史不混入，父晚到、循环、未知归属不误挂载。
- 单智能体、多子智能体、超过六条和嵌套分支均可访问，新增／排序／完成不抢选择。
- 主／子智能体点击统一在右侧辅助 Island 查看任务、活动、记录和结果；重复点击不闪烁，关闭不停止任务。
- 模拟慢读、无记录、部分记录、失败及 A→B→C 响应乱序，只显示当前目标；关闭、换终端或会话后旧响应不复活面板。
- 展开让位、切换、收起、反向重开无闪白、跳位或重复入场；减少动态效果可用。宽窗、紧凑、上下、聚焦布局可读可返回，连续 resize 不抖动，焦点和 Esc 层级正确。
- 新消息只在贴底时跟随，读历史和加载更早记录不丢锚点；崩溃后不永久执行中，无结束证据不误报完成。
- 三家 fixture、registry 归属／状态、IPC 分页与竞态、Island 浏览器交互、真实 CLI 主子任务检查分别留证。当前仅完成源码分析和设计记录，以上功能验收尚未执行。

## Alternatives considered

- 先完整开发独立 CLI 监控可较早改善终端查看体验，但其完整正文与详情交互容易和未来对话框重复建设；采用对话框先行、公共视图形成后接入 CLI 的顺序，代价是 CLI 监控收益延后。
- 旧左栏正文方案改动较少，但不符合本次右侧辅助 Island 要求；左栏保留身份和摘要。
- 新抽屉／中央 pane 会重复已有布局、动效和关闭逻辑，偏离 Island 状态层边界。
- 新子智能体 hook 可能更实时，但违反不新增 CLI 装订约束；未来稳定订阅可接统一契约。
- PTY 解析或时间邻近猜归属受重绘与并行会话影响，使用显式身份和父子链。
- 全量预加载或每次点击重开面板增加读取、内存与跳动，采用按需有界读取与单辅助面内容切换。

## Consequences

- **Gains**：开发投入优先服务未来主交互，CLI 监控复用经过真实场景验证的智能体展示与阅读能力；终端、主子智能体与任务内容仍保持完整路径。
- **Costs and limits**：完整 CLI 监控延后，复用程度尚待双来源验证。各家格式漂移、写盘延迟与状态证据缺失仍需独立适配；历史三家样本不能替代当前版本验证。宿主扩展、状态消费者更新和正文竞态保护都是实际实现工作。
- **Revisit when**：对话框多智能体展示可用时尽早用一个 CLI 验证复用；若真实使用证明 CLI 用户频繁切换检查或任务长期等待人工处理，再重评监控优先级。CLI 提供稳定订阅、写盘延迟不满足需求或某引擎维护成本过高时重新评估并明确降级；加载时序与缓存预算随长会话实测调整。
