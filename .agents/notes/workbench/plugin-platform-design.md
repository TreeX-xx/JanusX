# 插件平台与全产品扩展架构

## 定位与实现状态

JanusX 的目标是允许用户通过公开协议开发完整功能，组合中部工作区、工具箱、右侧栏、Island、独立工作台及宿主业务能力。插件可以只贡献命令、主题或服务，也可以形成跨区域应用。已有功能逐步使用相同贡献语义，用户能够管理其入口、启用范围及后台行为。

用户已认可该架构方向并要求形成设计和实施计划。本文维护目标设计，保留 draft 表示仍需逐阶段细化与验证，不表示下述 API 全部已实现。S1–S3 的可信视图、内置迁移与 CPA 已交付；P0 的[首版契约](plugin-contract-v1.md)及 P1 的 SDK 类型、严格校验、独立脚手架、命令／入口和旧 launcher 适配已落地。P2 已加入本地目录登记、授权、隔离桥、私有 KV 和管理调试；页面采用独立离线 Session 的 WebContentsView。P3 已加入通用视图 registry 的工作台／Island 位置、工作台返回及声明式 Island 状态／动作／受限文本预览。P4 首片接入嵌入文件编辑器的只读 viewer 匹配、默认选择、失效回退和逐文档隔离实例；隔离、限额与生命周期规则归首版契约，验收证据归阶段计划。P4 后续已接通版本化草稿交接、内置编辑器审阅保存、写前版本检查及未保存关闭保护；持续宿主草稿、人工冲突审阅、精确目录查询和通用工作区多实例已补齐；跨进程强事务、自动文件订阅及其它提供者仍待实施；P5 已采用宿主声明式任务接通无页面运行、任务监督、受限 HTTPS／凭证代理及事件／公开服务。

验收归[架构需求](requirements/plugin-architecture-forms.md)与[导入需求](requirements/plugin-import-debug.md)，阶段和参考工作量归[实施排期](../planning/plugin-platform-roadmap.md)。[PI-Desktop 调研](ideas/plugin-platform-and-feature-modularization.md)保留固定源码基线、机制比较及功能迁移机会。用户已采纳 Mermaid 图表预览作为官方插件案例，当前仅记录、尚未实施，范围见下文；项目健康看板不构成平台前置需求。

## 宿主、功能与运行方式

宿主负责项目身份、窗口和布局、文件与文档事务、会话及进程生命周期、凭证、授权、审计和持久化基础。官方功能扩展和第三方功能扩展通过贡献协议组合这些能力。内置扩展继续使用可信 React，普通第三方扩展使用隔离页面和宿主代理 API；共享贡献语义不意味着共享全部权限。

新增使用已开放接口的插件不应逐个修改宿主容器；新增贡献类别或新的宿主能力仍需要宿主实现和发布。既有终端、权限链和更新器保持基础设施职责。暂不以全量搬迁源码到 packages 或所有官方功能独立下载为前置条件。

## 命令、入口、视图与能力

| 契约 | 职责 | 典型描述 |
|---|---|---|
| 命令 | 用户可以发起的操作 | ID、标题、参数 schema、处理方式、可用条件 |
| 入口 | 操作出现的位置 | 工具箱、菜单、快捷键、文件上下文菜单、Island 动作 |
| 视图 | 插件的内容页面 | ID、资源入口、作用域、支持的展示位置、实例策略 |
| 工作台 | 一项完整功能的顶层界面 | 入口、根视图、进入／退出、内部导航和恢复描述 |
| 宿主能力 | 访问项目、资源或执行动作 | API 版本、权限、资源范围、取消、错误和限额 |
| 提供者 | 为特定领域增加实现 | 模型供应商、查看器、执行器、通知渠道等专用协议 |
| 服务与事件 | 不依赖可见页面的工作和协作 | 激活条件、订阅、任务归属、消息 schema 和版本 |

一个插件可声明多条命令、多个视图及入口，同一视图可由多个入口打开。工具箱需要支持操作与模板，不再仅依赖“筛选中部视图”的实现。声明式可用条件按宿主上下文求值，不执行任意条件脚本。菜单显示条件只影响可达性，运行时仍检查权限和参数。

一个视图实例由插件、视图、实例键及作用域共同确定。多位置共享业务状态不要求复用同一个组件或 DOM，也不承诺所有视图均能任意换区。公开清单为可序列化数据，图标使用受支持资源或令牌；第三方无需依赖宿主 React、私有 store 或 IPC。现有 `ExtensionDefinition` 的组件和同步激活继续作为可信适配层，公开异步加载不直接塞进同步注册流程。

## 界面贡献

| 位置 | 开放内容 | 宿主负责 |
|---|---|---|
| 中部工作区 | 工具 Tab、画布、文档、查看器和编辑器，可声明单／多实例 | Tab、分屏、焦点、关闭协商、脏状态及布局恢复 |
| 工具箱、菜单和快捷键 | 打开视图、运行操作、创建内容及应用模板 | 分类、搜索、排序、固定、冲突与用户显隐设置 |
| 右侧栏 | 树、列表、摘要、检查器、选中对象详情 | 宽度、折叠、顺序、上下文和挂载策略 |
| Island | 状态、进度、徽标、快捷动作、预览卡和展开工具区 | 外壳、动效、通知队列、焦点、打断和审批展示 |
| 独立工作台 | 类似蓝图的完整界面，可包含插件自己的导航、列表和详情 | 进入／退出、返回原界面、作用域与恢复 |
| 独立窗口与悬浮工具 | 视图的可选窗口形态及桌面小组件 | 原生窗口、置顶、位置、关闭和实例归属 |
| 文件与编辑器局部 | 文件打开贡献、右键操作、格式化、诊断和状态栏 | 匹配、默认选择、冲突处理、失败回退及键盘路由 |
| 对话与工具结果局部 | 消息操作、回复附加内容、输入区动作、插件自有工具卡 | 消息数据范围、用户操作语义和内容布局；不替换消息耐久层 |
| 设置、主题与模板 | 声明式配置、主题令牌、角色／皮肤资源、团队模板 | 校验、凭证输入、默认值、命名空间与失败回退 |

Island 首先采用宿主绘制的声明式状态、进度和动作，之后扩展受限预览及工具区域。复杂编辑进入插件页面或工作台。权限和审批提示处于宿主保留层，插件不能覆盖或冒充。角色外观与行为能力分别授权，不因加载皮肤取得会话或执行访问。

独立工作台首先由一个隔离根页面组织内部 UI，避免将首版工作台变成跨插件布局引擎。工作台与系统窗口分别建模；一个功能可以占满主窗口而不创建新的原生窗口。跨插件面板拼装及任意视图脱离／换区需要后续独立契约。

P7 首片已开放显式授权的 `window` 视图，复用离线页面和受限桥，由宿主负责单实例聚焦、原生关闭、项目／worktree 撤销和几何位置恢复。应用窗口可跨项目保留；设置／审批遮挡时分离插件内容。没有任意 pane 脱离、置顶／透明化或启动自动重开。当前边界归[窗口生命周期契约](plugin-contract-v1.md#p7-独立窗口生命周期)，Windows 证据归阶段计划；声明式调色板及其与既有配置的隔离已接通，设置／审批保持内置颜色；角色／皮肤资源及对话局部贡献仍未交付，AC-16 保持开放。

查看器按文件名／格式等明确条件匹配，支持用户选择、默认值和失败回退。编辑器通过宿主文档服务保存，处理版本冲突、未保存内容和外部变更，不直接覆盖宿主内部状态。普通文件读取与保存分别授权。

## 插件设置与参数配置

插件可以贡献自己的设置项，宿主在“设置 → 插件 → 配置”统一承载；配置与启停、权限授权及插件私有业务 KV 分开。基础版采用声明式字段，宿主生成布尔、文本、数字和枚举表单，负责默认值、说明、校验、保存、恢复默认与失败反馈。应用配置作为默认，允许项目覆盖的字段可在 project/worktree 下独立覆盖；界面明确正在编辑的作用域，插件只能读取自身绑定作用域的有效值，并订阅变化。配置不自动授予网络、文件或执行能力。

新增工作包 P4a 已实现上述声明式基础版，安排在 P5 网络／凭证和 P6 提供者之前；契约归[插件参数配置](plugin-contract-v1.md#p4a-插件参数配置)，实际证据归阶段计划。旧配置遇到字段删除、类型或范围变化时保留原数据、报告不兼容项并使用合法默认／继承值，不执行插件迁移脚本或让整个设置页崩溃。更新使用版本检查，避免旧表单覆盖新配置。停用／卸载保留配置，“删除插件数据”才清除。

自身配置导航已接通：插件可在页面／内部菜单调用受控 SDK 方法，可信外壳也提供入口；宿主展开并定位自身参数表单，按页面绑定选择应用或当前项目／worktree 层，设置遮挡沿用现有生命周期。声明式字段重命名迁移由宿主预览并经用户显式应用，逐层版本校验、保护已有目标与不兼容旧值，不执行插件迁移脚本。复杂插件已可声明应用／项目隔离工作台配置页并把建议值交给宿主表单审阅保存，普通表单保留回退；类型转换／迁移历史及敏感字段属于后续增量。API Key／Token 使用宿主凭证存储和引用，普通设置接口、日志及插件 UI 不返回原始密钥；这部分已由 P5 的独立加密凭证槽和宿主代用接通，不使用普通 KV 或配置字段存密钥；凭证请求当前仅返回状态，详细限制归首版契约。

## 上下文、状态与生命周期

按实际需要交付稳定的项目、worktree、窗口、文档、选择和会话引用，不默认交付所有会话正文或磁盘路径。应用级与项目级作用域分开；异步操作绑定发起时的上下文及激活代次，项目切换或停用后迟到结果不能污染新实例。既有内置面板的应用级外壳及旧 ID 由兼容适配保留，不能借扩展改造悄然改变现有项目切换行为。

宿主保存可序列化布局与恢复描述，插件保存私有业务数据并提供必要的数据迁移。应用级、项目级存储隔离，配额、写入失败和卸载后的保留规则公开。跨视图状态使用插件私有存储或插件自身服务，不依赖 React 局部状态永远保活。

| 操作 | 语义 |
|---|---|
| 隐藏／失活 | 页面暂不可见，可暂停非必要工作，不等于结束任务 |
| 关闭视图 | 释放该视图资源，先处理未保存内容；任务按既定归属继续或取消 |
| 停止任务／服务 | 取消自有运行工作并释放句柄，不删除耐久数据 |
| 停用插件 | 移除入口、视图及自有运行资源，撤销订阅与请求；不终止宿主共享会话 |
| 卸载包 | 移除程序和安装登记，用户数据默认保留，失效布局安全回退 |
| 删除数据 | 用户明确选择的独立动作，不附带在关页或普通卸载中 |

生命周期覆盖校验、安装、授权、激活、暂停、停用、更新和卸载。宿主按插件及激活代次管理资源，部分激活失败也必须回收；共享服务按真实消费者处理。自有后台任务由宿主监督，支持状态、日志、取消、超时和故障重试，不寄托在不可见组件的计时器中。

## 宿主 API 与提供者

| 领域 | 目标开放能力 | 关键边界 |
|---|---|---|
| 项目与文件 | 项目／worktree 上下文、受限读取、按需目录查询、受控文档保存 | 真实路径范围、项目归属、大小／频率限制与写入冲突 |
| 界面与存储 | 视图导航、主题／语言、提示、选择、插件私有数据 | 只控制已声明贡献，不获取任意宿主 DOM 或他插件私有数据 |
| 任务与进程 | 声明任务、执行器、日志流、取消、测试／构建结果 | 参数校验、执行授权、进程归属、环境及退出清理 |
| 网络与凭证 | 域名受限请求、宿主代理、凭证引用、连接状态 | 重定向目标校验、网络范围、密钥代用、刷新和撤销 |
| 模型与 Agent | 模型代发、工具 schema、技能、工作流、结果追踪 | 风险与审批、预算、取消、输出归属；不把密钥交给 UI |
| 会话与知识 | 授权会话查询、Note／知识读取、受控导入导出 | 正文读取独立权限、身份与关系一致性、宿主事务 |
| 事件与互操作 | 有版本的事件、公开服务发现及请求 | 提供／消费声明、数据授权、命名空间、取消与循环控制 |

提供者使用专用协议增加模型供应商、检索源、查看器、执行器和通知渠道。普通用户和第三方插件不注册终端类型、CLI／会话适配器或 PTY 后端；这些适配由 JanusX 宿主维护，任务与执行器贡献不取得终端注册权限。提供者不自动替换宿主的凭证、审批和持久化机制。先交付有真实消费者的协议与至少一个代表实现，其它适配逐项排期，不能把“有 registry”记作支持全部提供者。

P6 首片已让内置 Agent 通过显式 agent.services 授权调用既有公开服务，与普通消费者共用 schema／版本和 P5 任务预算；审批、上下文、取消与结果归属由宿主掌握。公共状态提供者和适配指南已交付；后续片通过声明式任务增加宿主默认模型的受限文本生成和摘要服务，模型权限、预算与取消归[模型代发契约](plugin-contract-v1.md#p6-受限文本模型代发)。插件技能资源已支持按需发现／读取、宿主审阅全文及内容修改重授权，作为不可信数据返回，不注入系统指令或自动调用工具，边界归[技能资源契约](plugin-contract-v1.md#p6-插件技能资源)。顺序服务工作流已复用任务监督接通 UI／Agent 共同调用、原始任务输入映射和逐步结果追踪；启动前固定直接提供者，失败即停，不回滚已发生的外部操作，细节归[工作流契约](plugin-contract-v1.md#p6-顺序服务工作流)。固定文件文档上下文已提供显式授权、按需只读和版本追踪，项目页面／Agent 使用相同资源，契约归[文档上下文](plugin-contract-v1.md#p6-文档上下文提供者)；P6 按 Windows 声明式代表范围闭合。首片限制归[公开服务契约](plugin-contract-v1.md#p6-首片内置-agent-调用公开服务)。

MCP 作为工具接入适配，Skills 作为指令资源，均不替代 UI 与安装生命周期。JanusX 内置 Agent 和各外部 CLI 分别报告工具、事件、上下文与取消能力，不支持的 hook 明确不可用，不模拟成已接入。消息／输入区贡献同样按各会话宿主的实际支持开放。

跨插件数据默认私有，复用走带版本与 schema 的公开服务或事件。收到事件不等于取得读取正文、写文件或执行权限。敏感消息按授权过滤，自动化记录来源并限制循环、速率及负载。缺少必需依赖明确阻止激活，缺少可选依赖降级；不引入任意跨插件 IPC。

## 运行、信任与本地开发

普通第三方扩展采用隔离页面、声明式贡献和宿主代理 API。权限检查同时约束能力种类、资源／项目范围与当前用户策略，在每次调用执行。运行环境还必须阻止直接网络、文件或执行接口绕过代理；静态校验和签名不能代替运行时检查。

S4 采用显式本地开发模式：默认关闭，由用户选择本地目录并确认声明权限；允许未签名页面在隔离环境中运行。主进程只读取清单、管理资源和处理授权 API，不执行插件 JS；开发模式不开放宿主 renderer、原生 Node、网络、写入、终端或模型后端。复制安装仍标记为本地开发来源，不能因复制目录获得正式发布身份。关闭开发模式阻止对应来源继续激活并清理运行资源。

正式发布的来源、完整性及签名策略归分发阶段，规则未实现前不开放正式来源自动激活。签名确认来源和完整性，不证明行为安全。若以后允许深度 renderer 或原生后台代码，另立可信模式并说明实际权限，不伪装为普通隔离插件。

无页面后台逻辑需要独立验证受限运行时。独立 Node 进程只提供部分故障隔离，不能作为强制权限沙箱；后台阶段先验证关闭直通访问、CPU／内存预算、取消与故障终止，再确定普通插件可用的运行方式。P5 试验确认 Node 权限模式仍能直通网络与环境，因此采用宿主声明式任务，不开放任意后台 JS。任务、网络、凭证、事件和公开服务的当前实现及预算归[首版契约](plugin-contract-v1.md#p5-后台任务网络与公开协作)，真实验证归实施计划；更强沙箱另行评估。

## 公开 SDK、兼容与用户控制

清单包含身份、包版本、宿主 API 兼容范围、能力需求、贡献、激活条件和权限。SDK 提供类型、定义与校验辅助、模板及独立构建入口。作者开发流程为创建模板、构建、本地导入、授权、运行、看日志、重载和校验交付，不需要修改 JanusX 源码。

SDK 只宣告已实现能力。缺少必需 API／贡献类别明确拒绝，缺少可选能力可以降级；保留版本化能力探测与弃用策略。开发日志包含插件／贡献／实例和请求关联，提供超时、错误码、调用追踪、故障熔断与重载清理。

用户可控制启用范围、入口显隐、固定／排序、快捷键、默认查看器及后台运行。安装不自动占满所有位置。官方必需功能与可选功能分别标记，停用影响可理解，独立更新包与完整卸载能力按依赖逐步提供。

## 蓝图官方可下载功能包

蓝图按需下载正在实施。[专项计划](../planning/blueprint-official-plugin.md)维护同仓库的 plugins/blueprint 独立源码、构建、签名目录和更新回退实现；原始 Notes、共享 Note／Agent 引擎保持归属，蓝图专属策略在受信 native 服务中复用共享事务。只有验证过的官方包、固定 signer allowlist 和明确授权可运行 native，独立进程拥有用户 OS 权限，不属于普通插件强制权限沙箱。UI 使用隔离页面与公开 SDK；稳定 MCP 启动器允许桌面关闭后独立使用，并保护存活进程持有的旧包。宿主旧 UI／业务适配、迁移、主包排除和完整验收待续；生产密钥、目录和资产未上线。AC-20–26 保持开放，局部测试不代表完整按需分发已交付。

## 官方插件案例：Mermaid 图表预览

用户已采纳 Mermaid 图表预览作为官方插件案例，本轮仅记录需求，不启动实现。它将文本形式的流程、时序或状态描述渲染为图形，补充现有文件阅读和编辑能力；普通文档阅读器及文本编辑器继续作为 SDK 技术示例，不重复包装为正式官方功能。

首片拟通过公开 document viewer 接口打开 .mmd／.mermaid 文件，提供图形预览、缩放／平移与语法错误提示；具体操作和验收在实施前细化。插件依赖公开 SDK，独立构建和本地导入，渲染库随包离线提供，沿用第三方权限及生命周期边界，不借官方身份使用私有源码或宿主接口。SVG／PNG 导出需先核对受控导出能力，Markdown 内嵌 Mermaid、源码编辑及自动刷新未确定纳入首片，不能记为已支持。

## 验证与后续细化

实施按需求 AC 与阶段出口记录单元、真实组件和 Electron 证据。至少验证外部仓库独立构建的双区域只读模板，后续增加跨工作台／Island 示例及无页面服务示例。测试覆盖项目切换与迟到响应、资源释放、拒绝权限、保存冲突、崩溃恢复、依赖缺失和更新失败；界面或代理替身通过不能替代真实隔离验证。

尚需在所属阶段细化：贡献字段及 API 命名、必需官方功能清单、后台运行时选择、首批提供者与已选 Mermaid 案例的具体范围、分发签名方案、跨平台支持矩阵。已认可的架构方向不依赖这些细节一次全部确定；首个可用交付仍为只读目录插件闭环。
