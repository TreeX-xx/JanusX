# Git 变更与提交图工作区

## Problem

变更文件和提交历史曾共享一个纵向列表，几百个改动会把历史推到视口之外。历史只取最近 100 条提交、缺少父提交和分支引用，无法表达分叉与合并。提交、同步和逐文件操作也缺少稳定的位置与主次。

## Decision

Git 面板保留工具区的 340–520px 宽度约束，采用常驻仓库栏和“变更／历史”双视图。分支、upstream、拉取／推送及领先／落后计数放在上方，刷新收入仓库菜单。视图各自滚动，键盘左右键切换标签。已有工作区毛玻璃过渡继续包围内容，仓库栏保持清晰；请求与操作仍跟随当前工作区的有效 worktree。

历史范围复用 JanusX 的 `Select`，统一触发器、浮层、键盘选择和 Escape 关闭；隐藏历史页或退出当前 Git 工具时关闭浮层。Git 操作控件使用中性文字、填色、描边与焦点环，包括提交、同步计数、搜索、下拉选中标记和确认弹窗。搜索匹配以字重和下划线表达，HEAD 标签与主轨道使用前景对比，不采用橙色强调。危险操作与增删差异保留各自语义色；样式覆盖限定在 Git 控件及其浮层，不改变其他模块的 Select 或提示框。

变更支持路径搜索和目录树／平铺切换。已暂存和工作区变更分别折叠，组头固定并提供全部暂存／取消暂存，目录显示匹配文件数。文件名为主，平铺时补充弱化的目录。行尾保留暂存操作，打开文件与放弃变更收入更多菜单。选中文件在独立详情区显示对应暂存层的差异；新文件、删除、二进制提示沿用真实 Git 输出。差异以 256 KiB 为上限并明确标注截断，可打开原文件。放弃仍需确认。

提交编辑固定在变更页底部，包含标题及可展开的正文。按钮明确显示已暂存数量，没有暂存项、没有标题、存在冲突或操作未结束时不可提交；不会隐式暂存全部文件。失败保留草稿。视图、搜索、折叠、选择、滚动位置和提交草稿按 workspace ID 与规范化 worktree 路径保存在当前应用进程中，切换和工具卸载后可恢复，重启应用不保留。

历史默认显示所有本地／远端分支和标签可达的提交，也可限定 HEAD 的祖先。后端新增独立的 `git:history` IPC，保留原 `git:log` 契约。每页默认 60 条，最大 200 条，以拓扑顺序返回真实父哈希、标题、正文、作者、日期及结构化 HEAD／本地／远端／标签引用。NUL 分隔避免竖线、中文与多行正文破坏解析；注释标签使用剥离后的对象。全部分支范围只走 heads/remotes/tags 和 HEAD，不混入 stash 或其他内部引用。[git-log](https://git-scm.com/docs/git-log) 与 [for-each-ref](https://git-scm.com/docs/git-for-each-ref) 定义这些顺序和格式语义。

图按父提交分配轨道，合并显示多条真实父边，未加载的父边延续到页面边界，无关系的根节点不相连。行高固定为 66px；复杂分支可横向滚动。当前 HEAD 使用主题前景色，其余轨道使用低饱和度颜色。分支、远端和标签紧凑显示。搜索匹配已加载提交的标题、正文、作者、哈希与引用，通过上一项／下一项定位并高亮，保持完整图结构；搜索框明确说明范围。点击提交在下方独立详情区显示完整消息和文件统计，合并提交相对第一父提交比较，关闭详情不改变行高。悬浮摘要保留不捕获指针的既有行为。

分页游标绑定 scope、HEAD 与参与遍历的 refs 指纹；读取前后或下一页指纹不一致时拒绝追加，并提供刷新入口，避免并发提交造成漏行或重复。分页和初次请求均受代次保护。失败保留已加载页；最多缓存最近八个仓库／范围组合，返回时验证指纹后恢复已经加载的页。提交详情失败有独立重试，旧工作区的操作失败不会覆盖新工作区错误。

## Alternatives considered

继续堆叠列表只改变样式，无法解决历史被改动推走的问题。上下分屏会让 340px 的侧栏同时承载两套短列表，阅读历史和批量审阅文件都受限。独立大型 Git 工作台有更大的图空间，但会引入新导航和窗口状态；目前保留单一侧栏，必要时可沿用既有宽度拖拽。

按搜索结果直接过滤提交图会隐藏祖先关系，绘制普通连续线容易误导。当前用定位与高亮保留拓扑；全仓库检索和过滤后的省略边是后续独立能力。分页简单使用 offset 而不验证 refs 则可能在外部提交后重复或漏行，故采用指纹拒绝并刷新。

## Consequences

大量变更不再影响历史入口，提交与同步位置稳定。新增图布局、分页和会话内视图缓存的维护成本；文件按 16 行分批使用 content-visibility，未变化的文件行复用，历史保留屏外布局跳过。窄栏复杂图允许横向滚动，未提供独立放大窗口；仓库搜索仅覆盖已加载记录，远端分支引用以本地已有数据为准，不自动 fetch。

验证覆盖 `git-history-service.test.ts` 的真实临时仓库：合并／分页、中文和竖线、正文、注释标签、远端 refs、HEAD 范围、无提交分支、游标失效、暂存／未暂存／删除／新文件差异、重命名与输出上限。`git-graph.test.ts` 验证多父边、共同祖先、独立根和追加页面稳定性。`git-store.test.ts` 覆盖并发去重、分页失败重试、跨工作区／范围迟到响应、缓存指纹和旧操作错误隔离。IPC 契约和既有 Git service 测试一并运行。

上述五个测试文件共 42 项通过；最后的数据格式与 stash／截断边界修改后，真实历史和 IPC 的 11 项复测通过。`npm run typecheck`、修改源码范围的 ESLint、`npm run i18n:check`、`npm run check:notes` 通过，Notes 为 0 错误、17 条既有外部链接提示。浏览器命令使用 `JANUS_E2E_PORT=41739` 与 `--project=island --workers=2 --timeout=60000`；最终 Git 八项单独以 `--workers=1` 全部通过。期间一次并行编译运行的首屏就绪检查超过 5 秒，隔离复跑通过，未将此作为桌面启动性能结论。

`git-workbench.spec.ts` 以 500 文件、85 提交覆盖双视图位置、分页搜索、键盘标签、草稿归属、仅提交已暂存、失败恢复及确认流程；深色／纸色与 340／520px 截图存于 `artifacts/git-workbench/`，已人工复核。配合 workspace-transition、right-workspace-design、right-tool-switch-performance、right-tool-tooltips、builtin-extensions 共 29 项浏览器验证通过。浏览器使用受控 IPC，真实 Git 测试在 Windows 本地仓库运行；未声称打包 Electron、SSH 网络或大仓库端到端性能已验证。

下拉和中性控件调整后，Git 八项浏览器回归、类型检查、修改源码范围的 ESLint 与 Notes 检查通过；回归补充 JanusX 下拉键盘选择、Escape 关闭和切换视图关闭浮层。深色／纸色 340px 两项复跑将截图保存到 `artifacts/git-controls-neutral/`，已人工复核展开菜单、启用的提交按钮、输入框焦点及同步确认弹窗，均无橙色操作强调。
