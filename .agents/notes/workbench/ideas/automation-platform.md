# Janus 自动化：卡片、定时执行与工程审查

## Intent

用户希望每天按提交版本审查代码质量，也希望通过 Janus 对话生成自己的自动化，选择内置 Agent、外部 CLI 或 Git 操作执行。首版已按下述范围实施；本文同时保留后续架构方向，不代表全部候选能力已经交付。本次未在用户项目启用实际计划，未创建工程 Task。普通自动化无需强制建立 Task；显式绑定已有 Task 时保留其验收和评审义务。

## 对话驱动的自动化方向与本轮实施

2026-11-03 用户确认先记录讨论，再以 xdo 实施一版。产品核心是把对话中的需求转换为持续执行的任务：对话理解触发条件、执行内容、资源范围和结果交付，生成可编辑草案；宿主负责校验、保存、调度、运行记录和通知。生成草案不等于已启用，成功回执必须来自真实工具结果。后续通过对话修改、暂停和查看任务。

采用固定动作与通用 Agent 两类执行方式。简单提醒由宿主直接通知，不调用模型；需要推理的任务由定时 Agent 执行提示词并交付结果。代码审查保留为专属模板，不再把 Git、审查和报告设为所有自动化的共同要求。项目按任务需要关联，无项目提醒必须可用。首版暂缓可视化 DAG、分支循环、多 Agent 和外部事件触发；真实场景反复需要时再扩展，控制开发和维护成本。

本轮先交付独立通知提醒闭环：自然对话生成草案、分钟间隔、编辑内容和周期、保存启用、试跑、停用与重启恢复，并回归原有代码审查。通用 Agent 任意任务执行、更多资源与事件触发作为后续阶段，不能将现有审查执行器宣传为已经支持通用任务。保持本地应用常驻约束，休眠或关闭期间不持续执行；恢复后不逐次补发积压提醒。

2026-11-04 任务中心调整：用户授权实施卡片内的任务增删编辑。采用任务独立调度、卡片只分组的模型：卡片持久化名称、ID、修订和创建时间，可为空；每个任务拥有自己的名称、周期、启停、执行定义、基准和运行历史。任务在所属卡片内直接新增和展开编辑，卡片只提供命名、折叠与整卡删除。审查里的 Git、Agent、检查和报告明确称为“执行步骤”；现有 `AutomationDefinition` 是独立任务，兼容存储字段 `tasks` 仍承载该任务的步骤链，不能与卡片内的多个任务混淆。

卡片保存在 automations/cards 下，任务通过 `cardId` 关联。旧定义启动时迁移为同名卡片中的一个任务，保留任务 ID、修订、周期、游标和历史；旧调用不传卡片 ID 时仍可创建单任务卡片。删除最后一个任务保留空卡片，删除一个任务不改变其他任务。新增、编辑、删除子任务都会使卡片修订递增，过期整卡删除确认不能误删后来的变更；整卡删除先落盘包含全部子任务 ID 的标记，再取消执行，在写队列外等待收尾，重启先清理这些任务再恢复编辑日志，防止迟到写入或崩溃恢复复活任务。

对话生成的新任务草案可选择已有卡片，也可保存为新卡片；已有任务草案仍定位原卡片，重挂载保留未保存输入，新草案不会被旧保存回执清空。任务通知继续用独立任务 ID 和运行 ID 定位。Island 收起后保留原双眼，不再显示角落圆点或底缘微亮；到达预览、单击查阅和展开态中性未读计数保留，详见[通知入口](../island-hifi-optimized-alignment.md#通知轻展开与主动查阅2026-11-03)。

## 执行模型与数据

| 对象 | 责任 |
| --- | --- |
| AutomationDefinition | 触发规则、项目身份、分支、输入、任务、执行器、输出与权限档位（首版仅只读报告），包含 revision |
| AutomationRun | occurrenceKey、定义快照、固定 commit、任务状态、executorRunId、产物、错误、检查覆盖 |
| AutomationCursor | 每条定义一条 lastReviewedCommit；定义修订或目标分支变化按基线冲突处理，不与最近一次触发时间混用 |

权限不做独立对象与撤销机制：首版仅只读报告档，随定义保存并在保存时确认；写入与发布档位随对应阶段引入。

首版采用顺序任务与显式输出绑定，不建设任意 DAG、可执行 JS 编辑器或条件表达式。每个任务有 id、kind、输入与结果引用；超时用固定常量，不做按步重试配置。Agent 输出只提供数据，不可解释为新代码或自动升级为 Git 命令。

| 任务类型 | 适用工作 | 实现方向 |
| --- | --- | --- |
| git | 解析 ref、固定版本、取 diff/log、创建分支或 worktree | 宿主类型化 Git 动作，显式参数和前置条件 |
| command | lint、类型检查、复杂度/重复度扫描、测试 | 固定 program/args/cwd；首版仅在模板显式开启且于自动化专用 worktree 中执行 |
| agent.internal | 语义审查、分析、报告或受约束修复 | agentX 运行时的新后台会话，固定工具与上下文 |
| agent.cli | 使用已安装和登录的外部 CLI 执行语义任务 | runner 适配器，检测能力/版本与结构化事件 |
| artifact | 校验报告结构、保存结果、发布宿主通知 | 宿主保存产物，模型不决定最终运行状态 |

内部与 CLI 执行器共享 start/cancel/recover/capabilities 契约，统一输出文本、任务事件、结束原因和结果引用；结构化完成优先于终端空闲推断。CLI 登录失效进入 needs_attention，不降级到另一账号/执行器。相同提示词切换执行器不保证相同工具能力，切换前重做能力与授权校验。

确定性 Git 查询与宿主校验不调用模型。首版不做自动重试，失败即结束并保留现场，重跑由用户手动触发；后续写入任务恢复前先核对实际 Git 状态。涉及工作树写入的操作按实际 repository/worktree 共享锁。

## 每日增量代码质量审查

建议模板名称为“每日增量代码质量审查”。默认首版只生成报告，以冗长分支、重复实现、跨模块依赖、异常处理、资源生命周期和测试缺口等可解释指标表达代码质量，不能承诺模型能可靠识别所有缺陷。

1. 在指定分支解析本轮 headCommit；若选择远程跟踪分支，先按配置执行 fetch，失败时报告不可获取，不静默使用陈旧远程 ref。分支在运行中继续前进不改变本轮 head。
2. 读取游标 baseCommit。初次运行默认从配置启用时的 head 开始；历史回溯由用户选择基准，不默认扫描全部历史。无新增提交则记录 no_changes。
3. 检查 base 是否仍为 head 的祖先。force-push、分支重建、基准对象丢失或浅克隆不足时进入 baseline_conflict；保留旧游标并提示重选基准，不擅自宣称覆盖。
4. 在 head 对应独立快照/脱离分支的 worktree 中审查 base→head 的净变化，并按需读取提交列表、调用者、模块 Note 与测试。该模式检查最终状态，不宣称逐条审查了后来被撤销的中间提交。未提交改动不进入本轮审查。
5. 先运行配置过的静态工具，收集复杂度、重复度、依赖和 lint 证据；随后 Agent 阅读变化与必要上下文，区分新增问题、因本次变更恶化的问题及存量债务。覆盖不全则标记 partial，不能输出“全部通过”。
6. 宿主验证发现项的文件、行号、固定 commit、规则、证据与建议；模型置信度是辅助信息，不是客观正确率。报告显示检查覆盖、跳过项及工具失败，而非只展示一个健康分。
7. 完整报告和覆盖证据耐久保存后，以比较并交换方式推进游标到 head。发现质量问题但完整完成审查时仍推进；执行失败、覆盖不全、取消或基线冲突时不推进。质量结论与执行状态分别记录。（2026-11-01 用户确认：游标仅完整覆盖后推进，不做入队推进与重试队列；连续两次覆盖不完整转 needs_attention 并提示重选基准，固定常量，不静默累积或跳过。）

报告至少包含 base/head、规则版本、检查命令与结果、覆盖范围和 findings。发现项带 severity/category/path/line/commit/evidence/suggestion；首版不做跨运行归并去重，相同问题可能重复出现。修改规则不自动回扫，也不沿用旧游标宣称历史符合新规则；需要重审历史时由用户显式重选基准。

项目测试、构建与 npm 脚本本身可以写文件或访问网络，“只读审查”不意味着它们安全或无副作用。报告模式应只开放审查所需工具；仓库脚本按配置在隔离工作区执行。Git worktree 只隔离文件变更，不是操作系统沙箱。外部 CLI 无法落实所需权限约束时标记能力不可用或要求选用明确允许的隔离环境，不能只靠提示词声称只读。

## 调度、恢复与结果

调度统一记录 UTC 时间点与 IANA 时区。首版支持每天、工作日、每周固定时间与手动触发；自定义 cron、事件触发与远程常驻后续加入。计划停用后不创建新运行，是否取消在途运行由显式操作决定。错过（应用未运行或休眠）在固定时限内补跑一次，超过则记录跳过，不无界补偿；时限用内部常量，不提供宽限设置。

运行与队列必须耐久保存。scheduled occurrenceKey 使用 definitionId + scheduledFor 防重，手动触发使用独立请求键；定义修订固定在运行快照中。采用至少一次调度与幂等任务，不承诺跨崩溃外部副作用 exactly-once。首版同一计划重叠默认跳过；并发复用宿主现有控制，不新增预算参数。

状态为 queued、running、needs_attention、succeeded、failed、cancelled、skipped、interrupted；预检等阶段通过任务记录体现，不单列状态。报告另记 reviewVerdict=clean/findings/incomplete，避免发现问题被当作执行失败。关闭页面不中断宿主任务；应用退出后首版停止调度，重启核对在途运行与产物，无法证明仍在运行时标记 interrupted，不凭 PID 相同自动重连。后续写入任务恢复前先核对实际 Git 状态。

取消传播到进程树；不提供预算、日志保留与磁盘限额设置，运行记录按固定条数上限维护（内部常量）。内部报告、产物与 Island 通知可自动发布，飞书/GitHub 等外部渠道是独立任务与授权。运行完成和工程验收分离：Agent 退出只代表执行结束，绑定 Task 的交付通过既有 Harness 检查与回执判定。

### 模块归属与关键处理

宿主独立模块为 `src/main/automations/`，共享类型与 IPC 单独命名，与知识库 automation 功能区分。界面通过现有内置扩展机制登记至右侧栏；本专题维护完整方案，工作台模块维护入口说明。普通自动化不强制创建工程 Task。

只读执行能力最先验证。现有 runner 的默认审批与自动放行不能直接作为只读启动档；内置 Agent 固定工具范围，外部 CLI 验证实际限制、完成信号与取消，不能仅靠提示词声称只读。静态命令仅允许模板明确配置，并在专用工作区执行；worktree 不等于操作系统沙箱。

报告与游标按可恢复顺序提交。单文件原子 JSON 写入不提供多文件事务；先耐久保存完整报告、覆盖证据及 base/head，再比较并更新游标。重启根据已保存报告核对未完成更新，仍须校验定义修订、目标和旧游标，不能覆盖新基准。失败、取消和覆盖不完整保留旧游标；连续两次覆盖不完整进入 needs_attention；完整审查发现问题仍正常推进。通知发布以耐久结果为依据。

复用底层能力，保持自动化独立生命周期。插件后台记录只在内存中，部分项目任务随当前项目切换取消，不能直接充当自动化账本或生命周期。自动化绑定创建时的项目身份，关闭面板或切换当前 UI 项目不结束运行，也不改变执行目标。蓝图调度器只参考调度与恢复实现，不复用其入队推进检查点的规则。

### 首版完成标准

用户能够创建并持续使用一条可靠的只读日报自动化。除下列范围检查外，真实执行验收覆盖进程树取消、未授权写入阻断、CLI 登录失效、连续两次覆盖不完整进入 needs_attention、定义修订冲突，以及关闭面板和切换项目后继续执行原项目任务。报告落盘、游标更新与通知发布之间分别模拟中断，核对恢复后的报告和游标一致性。界面验证覆盖草案编辑、试跑、保存启用、运行历史及通知定位；测试替身结果与真实 Agent／CLI、桌面端到端结果分别记录，不以卡片和开关可见代替交付完成。

### 阶段范围

第一阶段交付对话草案卡（一句话生成定义）、结构化定义、手动运行与本地定时、只读日报模板（内置 Agent 与一个经过能力验证的外部 CLI）、固定 Git 查询任务、耐久记录和游标。允许用户替换语义执行器；不开放任意脚本生成后直接启用。普通顺序任务足以覆盖首片，无需可视化图编辑器。

第二阶段增加具名 Git 写入任务、隔离分支修复、测试验证、既有 Task/Harness 绑定，以及单独授权的 push/PR。第三阶段再建设事件触发、更多 CLI/插件工作流、远程调度归属及独立常驻服务。

首片验证目标：无新提交不调用模型；固定 head 不受后续提交影响；失败/partial 不推进游标；完整 findings 正常推进；force-push/浅历史拒绝错误范围；同一 occurrence 不重复执行；重启不重复副作用；取消确实停止进程；未授权写入不能借通用命令绕过；外部 CLI 无登录/不支持权限策略时明确阻断；页面关闭不丢运行；游标保存与报告发布中断后可一致恢复。已执行证据与未测项分别记录在“当前实现与验证”。
