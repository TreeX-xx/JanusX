# 副黑板退役与 Island 下滑通知

## Problem

蓝图插件已有自己的工作台与入口。Island 副黑板退化为重复的插件列表，保留板高、工作区让位和开合手势增加操作层级。用户于 2026-10-27 明确要求删除，保持交互简洁。

## Decision

删除副黑板组件、样式、App 挂载、板高与拖拽状态、持久化读写及专属文案；不保留隐藏入口或兼容面板。插件继续经既有注册入口在自己的槽位打开。

Island 下滑 ≥60px 后松手展开通知，重复下滑保持展开；短拖、反向拉回和 pointercancel 均取消。peek 下滑先返回折叠胶囊再打开通知，expanded 不启用复杂手势。单击、Esc 和点击空白处仍收起，沿用通知面现有形变与看过即焚语义。

## Alternatives considered

继续让副黑板列插件可复用既有容器，但重复插件导航且保留无内容价值的布局状态。用户选择直接删除；本次不再扩展借调钉、文件钉或板内插件生命周期。

## Consequences

下滑与通知纵向展开一致，中央工作区不再因手势缩小或挪动。旧板高 localStorage 不再读取或写入；旧演示资产保留为历史来源，README 撤下过时 S2 动图，录制与验证脚本改为工具布局和跨项目切换。若将来重新需要副工作区，应以明确内容场景重新设计，不能恢复旧隐藏状态。

验证入口为 tests/e2e/island-interaction.spec.ts 的下滑、重复、取消和 peek 用例；共享 Note 原文失败重试、旧布局恢复和真实 Titlebar 退出确认迁至 tests/e2e/host-boundary.spec.ts。

## 历史设计与执行证据（已退役）

以下保留 2026-10-17 至 2026-10-25 的设计和当时验证，不代表现行功能或后续交付承诺。

### 灵动岛下拉副黑板：卷帘格局、钉住语义与借调规则

### Problem

原下拉手势曾把中央工作区翻面到蓝图，导致终端与参照互斥、入口重复及原生视图反复藏现，现已改为中央列副黑板。蓝图迁为[可下载插件](../planning/blueprint-official-plugin.md)后，黑板继续直接嵌入旧画布会让未安装用户加载蓝图业务，并绕开插件页面的单实例、作用域及可见性契约，需要继续收敛内容入口。

### Decision

下拉手势改绑**副黑板（副工作区）**：岛胶囊下拉 ≥60px，**中部工作区下滑让位**——板在中央工作区列的上带长出（高 220px～70vh，默认 420、下缘可拖），工作区是动画主体、随拖拽跟手下滑，不是从顶部盖下的卷帘。

**格局取「中央列 + 工作区下滑让位」**（2026-10-17 修订，取代首版切片的整窗宽覆盖卷帘）。三条边界：其一，板只占**中部工作区列**，左右栏架（侧栏、右坞/工具轨）全程可见可点——整窗宽覆盖会埋掉工具轨入口，且与「从文件树拖钉上板」的钉入口自相矛盾（操作面不可遮，内容面让位）；其二，动效主体是**工作区下滑**（下拉预览跟手、松手落点），岛胶囊本体不动，旧「岛跟手弹性下滑 + 工作区 rotateX 翻转预览」一并移除；其三，让位在拖拽中即时跟手（与右坞拖宽同语言），pty/原生视图几何随 flex 收缩自然结算——工作区容器变矮后浏览器原生视图 bounds 跟随矩形缩，不再需要板缘裁剪。板下缘 1px 发丝线作天际线；收板走下缘上推（低于 220px 落零）、收起按钮与 Esc 分层。

**判据取中断代价，不取能否交互**。收起时可 reload、可恢复的内容（原型、报告、预览）随便交互；中断有代价的内容（跑着的进程、未保存编辑、会话上下文）不上板。早期「黑板永不持有键盘输入」的规则作废——它与展开岛 chat composer 已收键盘输入的事实矛盾，且误伤交互原型这一核心场景。

**当前板面内容**：列出已启用扩展的非设置视图，宿主内置文件／Git／会话工具不在列表中。点击后经 `openExtensionView` 在该视图声明的槽位打开并收板，不另建插件页面。项目视图在未选择项目时禁用，应用视图仍可打开；停用立即撤下入口。无插件时显示安装启用提示，板头“管理插件”打开设置的插件页。旧蓝图画布与详情槽已经撤下，蓝图随官方插件在自己的工作台运行。文件钉、第二棵 pane 树及借调钉不在本次交付。

**三种钉（规划分类，当前交付不含文件钉）**：

| 钉型 | 内容 | 语义 |
| --- | --- | --- |
| 投影钉 | 蓝图活图（默认页签）、md 钉读、html/localhost iframe | 真身留工作区，板上是分身，双视图并存；收板卸载即可 |
| 借调钉 | 真浏览器 tab | WebContents 唯一实例换宿主矩形，工作区留占位卡；收板插值归还。iframe 盖不住通用网页（X-Frame-Options / CSP frame-ancestors），真网页只能借调 |
| 终端 | —— | 出局：不设交互终端，也不设输出 tail；盯输出走展开岛 monitor 与 RunOrb |

判定规则一句话：能造出廉价分身的走投影，造不出的走借调；两者都保证收板无代价。借调目前只有浏览器一个成员，规则通用——未来原生视图类内容（如 PDF 阅读器）直接套用。

**交互**：岛胶囊下拉 ≥60px 为 **toggle**——板未开则放下，已开则回收；pull-hint 文案随开合态翻转。收板另有板头 ChevronUp、板下缘上推和 Esc。单击通知中心、双击控制台、下拉黑板各自独立；启动已移到[顶栏运行按钮](run-orb-budding.md)，expanded 下复杂手势仍禁用。板内插件入口采用透明底、1px 发丝线及键盘焦点提示，不另建自由拖窗。焦点在 iframe 内时 Esc 归页面。未来借调仍须遵守唯一实例与无代价归还，不能直接复制原生页面。

**入口收敛**：`blueprintMode` 翻牌路径已退役，宿主工作台切换器不再内置蓝图按钮。旧 `activeWorkbench='blueprint'` 布局和旧通知动作引导到插件管理，不自动安装。新插件的入口及 Island 通知由贡献注册提供，宿主不订阅蓝图维护状态。

### Alternatives considered

- 继续下拉翻牌放蓝图——最强理由是零改动且保住初衷。否决原因是互斥隐喻与双入口冗余正是痛点根源；问题不在蓝图内容，在「一面一内容」的格局。蓝图该做黑板默认内容，而不是手势的全部目的。
- 黑板做第二棵 pane 树、收交互终端/编辑器——最强理由是副工作区名副其实、真缓解 pane 拥挤。否决原因是两个焦点域、拖拽落点、快照恢复与 pty resize 全套成本，且卷帘可随手收起的自由会被「收起即打断工作」毁掉，痛点翻倍。
- 预览一律禁止交互——最强理由是保住零键盘输入不变量。否决原因是设计工作流的核心产出就是可点交互原型，不能点的原型等于截图；判据改为中断代价后不再需要这条禁令。
- iframe 冒充通用浏览器——大量站点 X-Frame-Options/CSP 拒绝嵌入，不可靠；本地页与 localhost 由 iframe 覆盖，真网页走借调。
- 整窗宽覆盖卷帘（首版切片的默认）——最强理由是手势最省事、宽原型铺得开。否决原因是顶带会埋掉左右栏架：工具轨入口被盖住后「边看板边干活」不成立，且文件树被盖住时「拖钉上板」做不出来；宽内容留给槽位内部排版（md 钉读加阅读最大宽度）。
- 「覆盖不取让位」的旧取舍（几何稳定优先）——最强理由是瞥一眼节奏下 pty 不该抖。否决原因是它只在整窗宽覆盖的前提下成立；板限中央列后，工作区下滑让位的结算随 flex 收缩自然完成，拖拽跟手与右坞拖宽同语言，瞥一眼的开合成本可接受。
- 黑板改侧搭右列——最强理由是完全不遮工作区。否决原因是从顶部岛下拉的手势语义指向纵向卷帘，侧向属于右坞已有的另一套手势与布局语言。
- 终端给只读输出 tail 作为折中——用户明确砍掉；盯输出的需求由展开岛 monitor 与 RunOrb 承接，黑板边界因此更纯。

### Consequences

`useIslandGesture`、板高状态与中央列让位布局继续复用。插件入口交给既有扩展导航，减少未安装时的后台依赖；代价是无法在副板内直接预览蓝图，用户从入口进入插件原有工作台。视觉沿用 planche 纸底墨线、透明面板和 1px 发丝线。若以后需要副板内插件内容，须先提供 SDK 槽位与资源生命周期契约，再增加嵌入能力。

修订条件：出现「板上要敲命令」的持续证据→重启终端议题（当前明确拒绝）；用户长期开让位模式→常驻共存改道工作区分屏，而非继续拧卷帘；出现第二个原生视图类内容→直接套借调钉规则；文件钉需求回归→按三种钉分类重启，不走旧 `janus:blackboard-pins` 实现。

**当前验证**：当时的 `tests/e2e/blackboard-plugins.spec.ts`（已由 host-boundary.spec.ts 承接仍有效的宿主覆盖） 使用真实黑板、Titlebar 与工作区启动 hook，覆盖无插件管理提示、单实例复用、项目门槛、停用撤入口、旧布局恢复、共享 Note 原文读取、下拉开合及下缘拖高回收。合成扩展只证明宿主导航，不代表生产目录或蓝图全功能。未做：借调钉、文件钉、板内插件页面与过渡动效打磨。
