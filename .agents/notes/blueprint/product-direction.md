# 蓝图、Note 与个人画像：当前产品方向

## Intent

工程知识围绕 Note 与蓝图组织，当前以蓝图开发优化为主线；个人画像继续保留，本轮只做模块化剥离和必要代码维护，产品细化后移。本篇是当前讨论入口，区分用户已经确认的方向与仍需讨论的设计；阶段顺序和待讨论清单统一维护在[交付计划](evolution-roadmap.md)。当前实现和已运行验收见[实施基线](implementation-baseline.md)，本文不替代交付验收。

## 已确认方向

插件化保留原工作台的 UI 设计：第一栏项目、更新／建议、审核活动、Janus 和关闭，第二栏画布操作，左正文卡片／中蓝图／右侧可收起 Janus。首次打开显示加载动画和骨架屏，卡片与节点依次入场。独立包与宿主之间适配数据和授权边界；不得以迁移为由另行重构这套布局。当前实现及差异见[官方插件专项](../planning/blueprint-official-plugin.md#已确认的迁移回退与首次加载故障)。

- 插件化延续已有设置页与全屏悬浮卡片工作台设计，不随拆包另做界面：覆盖主界面顶栏，保留关闭／项目标题卡与一条操作栏，左侧阅读、中央模块画布、右侧讨论按需展开。左右卡片标题固定，内容独立滚动，右侧输入区固定在卡片底部；来源诊断与审核使用操作栏弹层，不额外占行。蓝图启动统一到工具箱，取消工具箱右侧重复的顶栏图标；打开后菜单显示“返回蓝图”和已打开标记，点击保留同一页面及讨论状态。设置中心与工作台快捷按钮使用同一设置页。Island 若由宿主操作展开则暂隐工作台并保留讨论状态；蓝图打开时不另露出主 Island 入口。插件迁移不等于改为中部 pane 或新建 OS 窗口。当前恢复与差异见[官方插件专项](../planning/blueprint-official-plugin.md#已确认的迁移回退与首次加载故障)。
- 工程知识库与蓝图在产品概念上融合，原“知识库”配置由蓝图承接；当前按[官方插件专项](../planning/blueprint-official-plugin.md)交付，安装后出现蓝图设置入口，卸载移除，不再内置于创新功能或固定设置页。
- 用户已取消独立关系图谱展示。蓝图沿用模块浏览、原文预览和既有关系详情，不提供“模块视图 / 关系图谱”切换；[导航模块](navigation/module.md)维护当前边界。
- 个人画像及个人记忆能力保留，其资料、确认、纠正、遗忘和对话使用不因工程功能调整而失去。仅采集用户输入、开启画像即覆盖内置对话并自动为所有已识别 Agent 终端接入 Hook 的已确认方向继续保留，移至后续个人画像建设。当前只做模块化剥离与必要代码维护，不将新机制或完整界面重做纳入蓝图交付；详见[个人工作台](../knowledge/personal-memory-workspace.md#当前范围已确认)，尚未改动运行机制。
- 审核融入蓝图并且只提供建议：是否修改及如何修改由外部编辑和用户授权的外部 Agent 决定，Janus 审核不建立强制采纳关口。右侧审核需要相应调整。
- 生成式 Agent 先分析并提出问题与候选建议，按配置由 JEV 核验问题依据；无 JEV 时返回标明未核验的 Agent 建议。分歧和调用失败保留真实状态，最终修改仍遵循外部决定和已有授权。
- 首版覆盖全项目的决策、模块、需求三类 Note，包括新增 Note、子模块及草稿/已生效/历史/归档内容，不开发指定范围功能。审核检查矛盾、遗漏和不足，读取必要上下文，Git 差异仅用于确认变化与辅助判断。优先跑通完整链路并保存开发验收证据，再逐步扩展；生产审核建议不保留历史。
- 自动审核静默、后台运行，不弹通知；蓝图活动区显示当前工作。用量管理只预留，当前不设上限；建议不保留历史，已处理或不采纳直接清理。目标 Note 删除后自动删除其建议，Note 与建议的各种联动由[建议管理模块](maintenance/suggestions/module.md)集中设计和维护。
- 自动审核采用 Git，累计全部提交（包括仅改代码），N 默认 5 且可调整，默认关闭；有目标 Note 差异才审核，首版不做差异过滤，没有 Note 修改不触发后续自动化。
- 启动审核前必须配置生成式 LLM，设置页检测配置；JEV 可选，配置完成不自动开启审核。左侧手动审核当前 Note，原文与建议同屏、建议可折叠；按概要/依据/处理建议/JEV 状态分层展示并可定位原文。
- 审核模型单独配置，建议生成模型从已设置好的生成式模型中选择；手动/自动审核共用这组配置，必须提供自动配置检测。右侧对话使用应用默认模型，后续支持指令切换；不连带切换审核配置。
- 不开发“复制给 Agent”功能；当前反馈交接使用已有宿主工具与同一 MCP，文件导出和本地反馈投影不列入交付。
- 压缩合并等特殊来源识别和补检暂缓，当前保留可识别普通合并的内部检查，不扩大自动审核频次。
- 新审核与建议仅由左侧手动及 Git 自动审核生成。右侧对话通过原生 MCP 读取已有建议，再按用户授权调整；不提供审核或建议生成触发，读取缺失/过时报告不隐式重审。
- 后续新版本暂时隐藏本地模型部署功能，尤其是设置界面的部署入口与引导；相关功能推进先放一放，保留既有实现作为后续恢复基础。
- 为难以采用 WorkflowX 的已有工作流提供独立 Note MCP，维护和读取 Janus 能识别的 Note。模块化设计与一键导入是明确要求；一键导入已明确为将 Note MCP 的服务配置导入对应 Agent 终端的用户级全局配置，同一种终端配置一次，供多个项目复用。MCP 是按 Agent 既有工作区权限运行的工具，不新增 Janus 专属审批；Janus 关闭后仍可读写 Note、读取已有建议并回写处理结果，自动审核仍暂停。

这些方向已经确认；具体工具、界面、配置检测方式、Git 计数异常与实施验收仍需细化。

## 推荐的职责边界

推荐以原始 Note 作为工程知识的唯一维护源。蓝图提供模块导航、阅读、编辑、关系和开发协作；搜索与 MCP 消费同一原文和可重建索引。审核补充质量反馈，避免形成另一套可以独立编辑的工程正文。

Note 随开发沉淀可以减少重复整理，但依赖 Agent 在适当时机维护。漏记、找不到和记录过时分别需要补录、读取改善与复核；格式和 MCP 本身不能保证业务判断正确。独立接入保留用户原有工作流，仍需最少的工具调用约定。

个人记忆独立服务用户偏好与长期信息，不自动写入项目 Note，也不进入工程检索或工程 MCP。实际代码与共享服务的拆分边界由主 Agent 在退出工程功能前核对，并随后续开发维护。

## 旧工程知识库退出与共享能力（已确认）

用户明确旧工程知识库资产采用删除清理策略；保留哪些共享能力由主 Agent 根据真实依赖判断，并在后续开发中持续复查和维护。清理在 M1.1 盘点、M1.2–M2.2 随共享能力接入逐步迁出，M3 完成旧工程退出（原 B3–B4 职责），不另要求用户逐项判断技术复用；本轮完成方向确认与初步依赖盘点，未执行代码或运行数据删除。

退出对象包括被替代的工程专用入口、采集/提取/发布管线、旧工程审核调度、工程 Wiki/图谱与检索/MCP 业务、无消费者的配置、索引及生成产物，并同步清理专用测试、依赖和失效说明。共享文件先拆分职责再删除工程部分，不能因路径包含 knowledge、memory、wiki 或 Hook 就认定整个文件可删；项目原始 Note 与蓝图 Note Wiki 属于当前维护源和阅读能力。

初步保留边界如下，具体代码去留以调用与数据归属验证为准：

| 能力 | 判断与处理依据 |
| --- | --- |
| 个人存储、确认/纠正/遗忘、召回及个人配置 | 保留并模块化解耦。现有 user-profile-service 依赖 truth-service、review-service 的锁及 audit-service；user-recall-service 仍依赖共享事实读取与 BM25，不能整包删除。 |
| 个人采集、可靠写入及维护调度 | user-memory 工具仍调用 observation-service 和 processing-queue；ipc/register 同时装配工程自动化及个人近期记忆维护。保留必要基础，移除工程专用调度，不让保留共享队列等于保留旧工程后台业务。 |
| 终端 Hook、事件桥接、状态与来源识别 | 保留终端仍使用的能力，工程采集订阅可单独退出。未来个人输入自动接入方向继续记录，当前不借清理扩展个人功能。 |
| 模型调用、JEV 接入与凭据 | 按蓝图审核的新契约复用或迁移必要能力；现有 knowledge-credentials 保存 JEV 凭据，不随旧业务删除用户密钥。通用能力复用不保留旧候选发布规则。 |
| Note 解析、身份/引用、版本校验及通用持久化 | 属于蓝图、MCP 或其他当前消费者的基础能力，继续维护；旧工程索引的业务包装可退出。 |

每次拆分或删除前更新实际消费者、存储归属与替代入口；删除后验证构建/调用无残留，个人现有操作、终端状态、蓝图与模型接入不受损。保留条目应有实际消费者或已确定的蓝图需求；后来失去用途时继续清理，不长期保留只为“也许会用”的旧框架。相关事实在所属模块 Note 维护，排期和范围由[交付计划](evolution-roadmap.md)收口。

工程生成数据按归属清理，混有个人事实、来源或历史记录的存储先拆分，不能删除整个共用数据根。先前要求保留的旧重构研究继续与当前设计隔离，必要历史验收依据保留可追溯位置；失效的现行说明随实现清理。此前“本地模型部署暂时隐藏、保留实现及资源”的决定继续适用，不把它扩大成模型文件删除。

## 设置、工作台与右侧审核的归属

已确认蓝图设置采用同页三个分区：审核模型（建议生成模型选择、独立 JEV 配置、自动检测与重新检测）、自动审核（默认关闭的总开关、默认 N=5 及触发规则说明）、MCP 接入（已识别终端、导入状态、一键全局导入、更新和连接检测）。日常审核、建议阅读与处理继续放在蓝图左侧预览；个人画像保留现有独立设置，本地模型部署入口隐藏。

设置修改后自动持久化并生效，不提供“保存”或“应用”按钮，也不要求离开页面才提交。开关与选项即时更新；文本输入自动校验，可合并连续输入以减少重复写入与探测。无效输入或写入失败在对应位置说明，不能把未成功写入的值显示为已生效；这些处理不增加手动保存步骤。模型连接检测异步刷新，配置写入成功与连接可用分别显示。MCP 导入、更新、重新检测属于各自操作，保留操作按钮，不作为设置保存控件。

| 入口 | 当前方向 | 尚未确定 |
| --- | --- | --- |
| 蓝图 | 全项目覆盖三类 Note；左侧手动审核与折叠建议同屏，保留原状态显示，有审核意见才额外提示；生成入口仅左侧手动与自动 | 静默后台与蓝图活动显示已确定，具体布局和外部反馈适配由实施完善 |
| 设置中的原知识库区域 | 已确认由蓝图承接，检测审核 LLM 配置；普通周期与合并专项共用一个自动审核开关，默认关、普通周期 N 默认 5；开启后合并专项检查含内部发现无通知合并的补检，检测细节待定；本地模型部署入口暂时隐藏 | 同页三分区与修改即生效已确认；具体字段、检测实现和旧配置映射待定，自动检查设置在能力交付后出现 |
| 原知识库工作台 | 个人工作台方向保留，细化后移；本轮仅在工程入口退出时维护个人现有访问路径 | 最终名称、页签、布局及个人记忆机制留待后续，不阻塞蓝图 |
| 右侧对话与原审核区域 | 项目侧通过原生 MCP 读取已有建议并维护，不发起审核或生成建议；个人记忆对象与动作独立 | 原生反馈工具字段、个人待确认项组织与旧界面调整 |

本地部署按现有本地模型的环境准备、资源下载及部署管理功能理解；新版本不将这些入口放入设置主流程，也不以完成应用内本地部署作为蓝图审核的前置条件。此决定暂缓产品入口与相关建设，不删除已有实现、已下载资源或用户配置；已有配置的兼容和运行中服务的处理在设置迁移时单独细化。本地 MCP 进程与已有模型提供方接入不因本项要求被一并隐藏。本轮只记录未来版本要求，未修改界面或运行服务。

项目审核与个人审核可共享展示组件，但对象、计数、动作和权限各自明确。项目侧呈现问题、依据、修改建议和复核；个人侧处理记忆的确认、纠正与拒绝。质量审核、写入授权、采纳决定和实施完成分别表达。

## Open questions

产品范围与本轮体验选择已收口，当前按 MVP 与完整版本计划推进；接口、存储、检测、视觉与清理细节由主 Agent 实施判断。JEV 质量与终端兼容性须以实际证据确定；压缩合并等特殊补检暂缓，不作为当前版本前置；个人画像扩展、本地部署和用量管理产品细化后置。
