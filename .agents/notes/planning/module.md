# 产品规划与版本排期

## Responsibility

维护 JanusX 跨模块的版本节点、工程排期与事项归入，为项目提供共同的节奏入口。各功能的设计、实现状态和验收仍由所属模块、需求与 Task 维护；排期条目不代替验收结论。

## Design

[工作区数据、读写与 Hook 生命周期总计划](workspace-data-lifecycle-plan.md)统一安排目录迁移、I/O 门控、Hook 单次启动隔离、工作区删除维护、残留退场及跨版本验收。P0 设计完成，P1–P5 已本地实施；P1 的[最小读写设计](workspace-data-contract-baseline.md)采用每批 32 文件、全局最多 64 个待执行任务和后台批间休息 20ms。用户已调度 P6，进程中断恢复、桌面迁移、真实 CLI 及 WSL／SSH 断线的代表场景已有证据，物理慢盘、正式安装器覆盖升级和连续多日运行仍待验收。各专项继续拥有设计和证据，局部通过不代表完整 P6 签收。

[个人开发工作台与团队产品的演进方向](product-growth-direction.md)记录个人优先、小团队上下文共享试点及 ToB 投入条件的策略探索，同时讨论工具箱扩展和 Notion 接入层次。该文属于待确认 idea，不改变既有排期或代表团队功能已交付。

[工程排期里程碑备忘录](engineering-milestones.md)集中保存版本节点与散点，按讨论结果持续调整。它属于当前规划资料，保留 draft 生命周期；版本号或经过时间不构成完成、失效或归档依据。

[插件平台分阶段交付计划](plugin-platform-roadmap.md)保留 S1 可信核心、S2 内置迁移、S3 CPA／双区域验证及托管记录。P0 契约、P1 SDK／校验／独立脚手架和命令入口、P2 目录登记／授权／独立离线页面／只读桥／私有 KV／管理调试均已实施。P2 收尾补齐真实 OOM／连续崩溃熔断、worktree 与文件边界证据、实时桥状态及跨启动入口偏好，S4 本地只读范围已闭合。P3 工作台／Island 已接入，P4 首片增加嵌入文件编辑器的只读 viewer、默认选择／恢复、失效回退和按文档绑定实例；后续片已增加版本化草稿交接、宿主审阅保存、未保存关闭及写前版本冲突检查；持续宿主草稿、人工差异审阅、精确目录查询和通用工作区多实例已补齐；跨进程强事务、自动文件订阅、代表内置查看器迁移及完整 P4 验收待续。新增 P4a 已交付声明式插件设置、应用默认／项目与 worktree 覆盖、恢复默认、读取订阅及旧值诊断；隔离自定义设置页与宿主审阅配置建议已接通，P5 已补齐凭证引用、宿主声明式无页面任务、受限网络和事件／公开服务。平台限制和实际门禁证据归阶段计划。P6 首片已接通内置 Agent 的公开服务调用、显式授权、取消与结果归属，已补齐受限文本模型代发、按需读取的技能资源与受监督的顺序服务工作流，固定文件文档上下文已补齐，P6／M3 按 Windows 开发构建的声明式代表范围完成。P7 已接通显式授权的独立窗口、单实例／关闭清理、几何恢复与宿主遮挡，声明式调色板与既有配置隔离已接通，角色资源及对话贡献待续；后续依[全产品目标设计](../workbench/plugin-platform-design.md)继续窗口个性化；第三方不能注册终端类型或 CLI／会话适配器。P8 对应 S5，不要求全部官方功能先迁移。计划保留依赖、参考工作量、出口和 AC 对照，版本未指定，任意后台 JS 的更强沙箱及分发工期需先试验。真实供应商额度与跨平台托管的验收边界仍归工作台。

[蓝图官方可下载插件实施计划](blueprint-official-plugin.md)维护按需下载目标下的代码边界、官方来源、接口试验、迁移与发布门禁。独立 UI／后台、签名分发、MCP、仓库外构建及旧数据导入已有实现和定向证据，构建与真实载体回归已接入本地及 CI 命令。插件树和宿主业务边界已清理，Windows 实物已有代表验证；生产目录、可消费共享修订、新版本完整功能与故障矩阵仍有缺口，BP-0–BP-6 不以局部测试通过签收，分发衔接 P8。

蓝图本地试用使用 `npm run dev:blueprint`，独立 profile、签名安装、启用和桌面关闭后的 MCP 已有完整桌面定向证据；不依赖 Release。BP-5 清理三个宿主入口、公共组件和作者工具，Windows 实物及三态资源已有代表证据，体积小幅减少而启动未见明显收益。用户已移除旧版升级兼容，暂缓撤销并取消对话修改审计；1.0.3 保留文件预览／确认，直接提交 Note 事务，右侧无审计和撤销入口。BP-6 继续验证新版本完整功能、故障及持续资源，生产目录与可消费共享修订仍待交付，详见[官方插件专项](blueprint-official-plugin.md)。蓝图专项的[产品方向](../blueprint/product-direction.md)与[交付计划](../blueprint/evolution-roadmap.md)继续归蓝图维护，本模块引用专项计划而不复制其正文。应用内备忘录和星座里程碑的产品能力归[个人记忆与共享来源](../knowledge/module.md)，与这里的仓库排期资料分别维护。

项目 Notes 根目录仅保留项目入口，跨模块排期归本模块。新增专题使用稳定文件名并声明本模块 URI；以后明确退出当前排期的资料可移入本目录的 history/，同步生命周期、引用与维护时间。归档是另行确认的内容处置，不由目录整理自动推断。

蓝图下次继续从专项的[后续接续入口](blueprint-official-plugin.md#后续接续入口)恢复：worktree 选择、正文往返、独立维护写入／建议处理和旧页面等待确认取消已有代表证据；每个蓝图只作用于本 worktree。接着补高频切换、迟到模型输出、长期资源与配套实物；外部 MCP 先补 Codex 写入验证和 Pi 扩展接入，实际兼容矩阵由 Note MCP 专题维护。
