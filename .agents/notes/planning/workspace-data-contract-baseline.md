# 工作区私有状态契约与最小读写方案

## 状态与原则

用户要求保持简单，避免难维护的大量阈值。2026-10-29 将 P0/P1 收敛为统一排队、请求去重、分批处理和必要的数据保护；撤下双令牌桶、每秒速率、多级优先级、压力窗口、自适应降速及复杂配额参数，不再作为实施要求。用户已调度 xdo 实施 P1；统一门控已落地并完成主 Agent 测试。P2–P6 仍由用户分别调度。

[总计划](workspace-data-lifecycle-plan.md)维护阶段安排；[存储专题](../desktop/workspace-state-storage.md)拥有身份、升级和清理规则；[Hook 专题](../terminal/terminal-hook-launch-isolation.md)拥有单次启动隔离。本轮不同时重写存储引擎、引入生命周期数据库或制作通用资源调度平台。

## P0 最必要的契约

数据使用稳定 storageId；显示名称与路径可变，worktree 和远程环境分别识别。沿用有效 userData 的 profile 隔离，移动目录通过重新定位处理，离线不是删除。源文件、Git、Notes 和构建产物不迁移。生命周期时间持久保存，升级不刷新原到期时间。

宿主提供轻量队列和路径解析接口，agentX 注入使用，不依赖 Electron。P1 沿用现有路径，以运行环境和已验证目录作为队列键；P2 再接稳定身份与 userData。保留排队执行、共享进行中查询、取消和分批执行即可，不预建复杂服务体系。

Agent 修改前必须完成保护快照，失败则不修改。只有完整且已提交的快照才可恢复；创建与 GC 不交错删除引用。日志通过受限资源读取，不能访问任意 userData 路径。Hook 仅对本次启动接入，不改用户全局配置，兼容性逐引擎验证。

## P1：一个队列、去重、分批

所有受管重型扫描和持久化共用一个宿主队列，同一时刻只执行一个读写批次，避免每个终端各自开并发。不同目录在批次之间轮转；小型配置保存、元数据读取和日志刷盘可以在批次间执行，不必等待一个全目录扫描结束。同目录修改、恢复与引用变更保持顺序，事务未结束不能插入冲突操作。

这里只限制宿主自有工作，不限制外部 CLI 或编译器。多进程写同一状态目录时先保证存储所有权互斥，不另建跨进程配额系统。后续迁移和 Hook 资产准备复用同一队列，不自行增加限流器。

队列只保存小请求描述，不预读文件正文。首版只保留批次大小、待执行任务总上限和后台全量扫描批间休息三个内部常量，不做用户设置或自动调参；队列满明确返回忙碌。文件、日志和文本继续沿用现有大小保护。终端关闭释放基线和无用请求，不保留无限历史。

用户已确认首版值：每批最多处理 32 个文件，全局最多等待 64 个任务。32 是文件操作批次上限，不是同时打开 32 个文件；大文件和日志沿用流式分块，读写块之间也让出执行权。64 按合并重复请求后的待执行逻辑任务计数，不按文件数计数，不含正在执行的任务；任务的后续批次不再次占用新的任务名额。超过上限返回忙碌，不产生隐藏的第二层等待队列。

后台全量扫描每批之后固定休息 20ms，作为首轮实现值；这段时间其他后台重型扫描也不能接替消耗磁盘，否则休息失效。界面处理、小型保存和元数据请求仍可执行。写前保护、显式恢复不主动加这段延时，仍按统一队列分批运行。此规则只为后台扫描留空档，不宣称所有情况下磁盘都不会满忙；不添加压力检测和动态策略。三个常量仅在实测有必要时修改。

### 多终端如何处理

| 请求 | 规则 |
| --- | --- |
| 多终端恢复快照、Agent 写前保护 | 逐个排队，独立恢复边界不能合并 |
| 同目录初始化 | 共享一个进行中的 Promise，失败后允许重试 |
| 同目录相同统计查询 | 共享一次扫描；执行中有新变化只标记需要再刷新一次 |
| 连续事件 | 只标脏，当前任务结束后处理最新状态，不新增定时阈值 |
| 回合前后基线 | 保留回合归属；错过边界则统计不可用，不累计归给下一回合 |
| 终端／工作区关闭 | 取消无用待执行请求，安全结束当前批次，不再向失效对象发布结果 |

列表只读元数据，空列表不扫描项目；需要统计或差异才扫描。缓存必须范围、身份和版本一致。首次必要捕获仍可全量扫描。利用现有监听记录脏路径、后续只检查变化文件是后续可选优化，监听失效时须完整核对；首版不实现该增量引擎，先消除重复扫描，效果不足再按证据单独设计。

### 大扫描、大写入和清理

文件枚举采用有界迭代，内容读写用固定大小缓冲，每批结束让出并检查取消。终端现有八文件并发必须接入队列，不能在队列外与检查点叠加。Git 枚举最多一个，不按每次刷新重复启动，失败不立即转无界递归；Git 内部 I/O 无法由 JavaScript 批次直接限制，实测需注明。

日志流式分块落盘、采用标准流背压，沿用现有截断上限并明确标记，不等退出集中拼接大输出。配置、索引串行原子保存。快照先写完整内容再发布引用；同目录创建、恢复与 GC 互斥。GC 只在前台队列空闲时运行，每批结束检查新请求，有请求就让出；一批淘汰结束后统一回收，不每删一个重扫全部内容块。

执行权与事务保护分开：批次让出后其他目录可继续，同目录冲突操作不能插入半完成事务。先用普通队列和目录互斥实现，不建设通用租约调度框架。大量哈希、JSON 和 diff 同样分批或移出主线程，不能只把文件读取异步化后仍阻塞界面。

### 安全边界

写前保护失败不继续修改；部分扫描不冒充完整恢复快照。JanusX 显式发送整条提示如需提交前快照，应先捕获再发送；外部 TUI 输入无法可靠拦截时不承诺严格写前边界。回合错过边界或基线失效时显示不可用，不伪装零变化。失败不无限自动重试，等待可显示忙碌并取消。

## P1 最小实施顺序

1. 建立唯一队列，接检查点；共享初始化和查询，分离元数据列表与统计。
2. 接入终端回合扫描、Agent 保护、日志及 GC，改为分批，补齐目录互斥和取消。
3. 测多终端、大目录和大日志，验证没有扫描叠加、无限积压或引用误删。

不做动态磁盘压力判断、按秒令牌限流、多优先级老化和自动调参。P1 期间不迁移真实数据，P2 再切 userData，P3 再改 Hook。P1 已由用户调度实施，后续阶段仍需分别调度。

## 最小性能验证

使用独立 profile 和 fixture，保留三个场景：普通项目重复查询和少量修改；大目录多终端捕获并触发清理；大日志输出及中途关闭。记录设备、源码版本、缓存状态和操作序列，比较实际扫描次数、峰值并发、累计读写、队列排空及界面响应。不建设生产监控平台，不逐文件打印性能日志。

必须通过：相同查询不重复扫描，重型批次不叠加，大任务分批让出，后台扫描遵守批间休息且不能被其他后台扫描填满空档，取消后不继续积压，保护快照不绕过，GC 不误删，升级不重置到期时间。单个 I/O 或前台连续操作仍可能让慢盘满忙；实测不足再按证据调整，不预先引入整套阈值系统。

## 实施与验证

P1 已实施。agentX 的 WorkspaceIoQueue 提供同一进程共享执行通道；JanusX 的终端捕获、检查点、Agent 写前保护、配置与命令日志接入。目录事务在让出执行通道后仍持有所有权；空闲 GC 每批释放所有权，并在恢复时刷新引用。清理中出现变更只标记一次补扫。未知格式、损坏或无法读取的快照元数据停止自动块回收，避免按不完整引用删除数据。初始化只加载元数据，不创建空目录；列表统计为 null，明确表示未计算，用户请求明细时才扫描。

运行常量为 32 文件／批、64 个等待逻辑任务、后台批间休息 20ms；运行中任务的续批不增加队列名额。文件内容使用 64 KiB 分块读写，这是固定缓冲实现大小，不增加用户阈值。命令日志采用标准 Writable 背压，保留原有每流 10 MiB 上限和 8 KiB 预览。项目运行器仍保存已有最多 1,000 行尾部日志，在退出时分块写入；没有扩建完整实时日志服务。关闭终端取消等待任务，并阻止失效结果发布。外部 TUI 输入仍先到 PTY，不承诺可可靠拦截的严格提交前快照。

验证命令与范围：agentX 的 agent-core 全量测试 24 文件、377 项通过、1 项原有跳过；node-hosts 的 command-tools/jobs 23 项通过，包含真实子进程 100 MiB 输出。JanusX 定向回归 13 文件、70 项通过，覆盖查询合并、70 次连续回合与关闭取消、输入事务、终端 IPC、运行器与配置。两依赖包构建、JanusX typecheck、定向 ESLint 与 build:check 通过。这里是主 Agent 自动化验证，未进行独立评审或桌面手工验收。

## 当前出口与限制

P0/P1 首版实现与上述验证已完成。P2 路径迁移、P3 Hook 隔离、P4 长期删除维护及 P5 残留清理均未执行；当前仍按旧路径保存到 .janusX。应用升级不重置到期时间的完整迁移验收属于后续阶段，不能由本轮队列测试代替。

队列只管当前进程内接入的调用；独立 CLI、多实例和外部编译器没有跨进程资源配额。慢盘物理占用 100%、真实 UI 延迟、远程端和长时间运行尚未实测。Git 子进程最多一个、输出限制 16 MiB，内部 I/O 无法被 JS 批次控制。目录枚举采用 opendir，文件路径和快照索引仍随文件数增长；单文件哈希、JSON 编解码及单文件 diff 仍有同步工作。后台 20ms 休息可能使大文件冷扫描更慢；如后续慢盘或超大索引验收不足，再按证据拆分热点，不增加预设阈值系统。
