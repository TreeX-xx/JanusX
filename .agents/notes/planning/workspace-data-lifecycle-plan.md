# 工作区数据、读写与 Hook 生命周期总计划

## 调度约定与当前状态

用户要求将目录迁移、读写优化、Hook 机制、删除维护统一为一个大计划，由用户逐项调度。本篇是总入口；P0 设计完成，P1–P5 已完成本地实施和定向验证。用户于 2026-10-30 调度 P6，本机进程恢复、桌面迁移、真实 CLI 和远程断线的代表场景已验收，物理慢盘、正式安装器升级及连续多日运行仍待验证。P5 的主动清理保留无法确认的旧文件并列出原因，不等于已删除实际用户 home 中的全部历史接入。本轮直接执行，不创建 Task，也不迁移或批量清理真实用户数据。

P0/P1 的[最小契约与读写方案](workspace-data-contract-baseline.md)首版已实施，采用 32 文件／批、64 个等待任务、后台批间休息 20ms。P2 本地迁移、P3 启动注入和 P4 本地生命周期均已实施并有自动化证据；慢盘、安装包升级和长期验收仍归 P6。

P1 首版方案已收口：统一队列、初始化／查询去重、扫描与日志分批、后台全量扫描批间固定休息、空闲 GC 和必要事务保护。首版采用 32 文件／批、全局最多等待 64 个任务、后台扫描批间休息 20ms；增量扫描留待后续。撤下多阈值及自适应限速，不建设通用资源调度平台；P1 已实施，验证及限制见最小读写方案。

存储及读写设计由[工作区私有状态](../desktop/workspace-state-storage.md)拥有，Hook 接入、真实 CLI 探测与兼容缺口由[单次启动隔离评审](../terminal/terminal-hook-launch-isolation.md)拥有。总计划维护执行切片、依赖、出口与调度状态，不复制专项事实，也不将已有局部试验提升为完成验收。

## 总目标与边界

JanusX 私有运行数据默认由有效 userData 管理，不在工作区根生成 `.janusX`；Hook 的发送器、扩展和附加配置由 JanusX 拥有，只在本次 CLI 启动链加载。工作区名称、路径、身份与数据生命周期分离，升级不重置已记录的清理时间。统一排队扫描、查询、日志、迁移与清理，去重并分批执行，限制待执行任务积压，同时保持写前保护、恢复与内容引用一致性。

不迁移源码、Git、工程 Notes、项目依赖或构建产物；不隔离或替换用户原生登录／会话 home，不关闭用户扩展及 hook，不自动信任用户或项目 hook。不恢复已移除的会话还原点界面，不把用量统计重新绑定为依赖 hook，不承诺限制外部程序或系统整体磁盘活动百分比。

## 各专项必须保留的约束

读写优化优先削减触发和重复扫描。首版做统一排队、查询去重、分批让出及后台全量扫描固定休息，只保留对应的三个内部常量，沿用现有大小保护；增量扫描后置，撤下多层速率、自适应压力及旧复杂实验阈值。P1 原检查点恢复及 GC 契约已随快照退场转为历史证据；当前仍验证文件冲突、提交复核、队列顺序和 Island 差异完整性。

Hook 接入位置与事件可靠性分开验收。Claude 附加 settings、Pi extension 的已有证据仍有交互场景缺口；Codex 使用原生主动审阅，用户明确允许由原生保存信任；OpenCode 新 API 和独立服务已接入，按实际版本选择适配。版本矩阵与未验收交互由专项维护。默认不使用放开全部 hook 信任的参数，不伪造原生信任记录。诊断区分未执行、未投递、归属失败、状态转换失败和 renderer 未同步；不能用一段静默推定回合完成。

P3 必须遵守[遥测解耦决策的当前差距](../terminal/usage-telemetry-hook-decoupling.md#当前实现与纯后台边界的差距)：上下文、用量及其终端归属完全独立于 Hook，不能把 Hook 绑定保留为可选增强，也不能经统一事件总线间接触发遥测。现有后台扫描、上下文轮询、PTY 活跃度与原生会话相关性归属继续保留；只清理 Hook 残留依赖。Hook 的“会话绑定／更新”限状态、历史等非统计用途，不接入遥测 coordinator。个人习惯采集沿用现有路线，仅 persona 及对应选项均开启后接入，关闭时不得为其分发、排队、补读、持久化或推断；运行期关闭阻止在途采集和新结果提交。具体责任与验收归 [Hook 专题](../terminal/terminal-hook-launch-isolation.md)。

清理按稳定身份和持久化生命周期时间执行，不依赖显示名称、应用启动时间或迁移后的文件 mtime。正常升级沿用原 createdAt／expiresAt／detachedAt 等语义字段，不赠送新的保留期。用户主动迁移旧数据是显式例外：原创建时间保留，迁入数据时间保留期在首次成功切换时重新起算一次，失败、重试和后续升级不刷新。P2 已持久化 retentionStartedAt，P4 已接入解除关联与清理字段；manifest／registry 均为 schema 1，具体入口和迁移规则归存储专题。策略变更有显式过渡，未知格式保留；应用卸载、profile 切换与永久清除不能混为工作区移除。

## 单阶段执行与交接

用户可用“执行 P1”或“先做 P3 的 Claude 接入”等方式调度。启动时读取本篇和相关专项，核实前置状态、固定本次范围和验证命令；是否使用 Task 或独立审查按用户选定工作流处理，不由本篇自动创建或委派。完成后更新专项的事实、证据及本篇阶段状态，报告变更、验证、剩余缺口和下一阶段依赖，等待下一次调度。

P1 证据归最小读写方案，P2、P4 与 P6 存储恢复的实现和测试归存储专题，P3 验证与版本缺口、P5 清理及 P6 CLI 复验归 Hook 专题。此前三残留目录删除被审批策略拒绝属于历史记录；P5 已重新核实当前均不存在，本轮没有执行删除，也没有清理真实用户 home。

## P6 本机代表验收与剩余出口

`node scripts/verify-workspace-lifecycle.mjs` 使用真实存储实现和隔离目录，处理 257 个日志共 48 MiB、4,096 个旧快照，分别在复制和源清理中杀死子进程后恢复；完成内容哈希核对、未知文件和源码保留、前台插入、12 次独立进程重启及每轮 20 组八请求查询。旧来源不会覆盖迁移后新配置，回执和提示状态保持；跨 30 天保留期使用 API 时间参数加速，验证活动保护及解除关联到期清理，不能当成连续运行 30 天。指标和限制在本机 `artifacts/workspace-storage/p6-lifecycle.json`，存储专题维护桌面升级、降级和 profile 的证据边界。

本机回归 15 文件 178 项通过、13 项跳过；真实 CLI 四项通过，Electron 历史恢复一项通过，新增桌面迁移一项通过。相邻 agentX 的 `packages/node-hosts/tests/command-tools.test.ts` 和 `jobs.test.ts` 共 23 项通过，包含真实子进程 100 MiB 输出及日志上限，报告为本机 `artifacts/workspace-storage/p6-command-output.json`；未改动该仓库。真实 WSL／SSH 的单个定向用例验证传输关闭后同一 PTY 继续存活并读回断线输出，其余十项不在此次远程选择范围。测试 fixture 独立于用户项目、配置和登录；远程迁移仍不支持。未增加生产状态、版本历史表、调度器或阈值。

P6 仍缺物理慢盘、正式安装器覆盖升级、跨平台、连续多日资源与清理观测，以及真实账号的完整审批／中断交互。现有 0.9.4 实物到当前源码构建的升级不等于两份正式安装包升级；旧版无法读取已迁入的新目录，降级需要已备份的旧配置或显式导出，不提供自动逆迁移。下一次从这些明确缺口继续，不重复建设迁移机制或将局部结果提升为全阶段通过。
