# Agent 对话与执行

## Responsibility

WorkflowX v2 中，普通 xdo 直接使用工程工具，不要求建立 Task。Task 绑定执行由 Main 掌握整份文档，子执行上下文只读并返回实现摘要与 Note 草稿。交接在同一 Task 中更新；xdel 只自审，既有独立评审义务保留待办，xflow 和绑定该义务的 xdo 按固定 AC 独立评估。桌面接口保留未完成结果和草稿，模块状态不随 Task 回执自动变化。接入证据见 [WorkflowX v2](../blueprint/workflowx-v2-adoption.md)。

把 JanusX 的对话、工具、任务线程和执行回执接入共享 Agent 运行时。任务启动、验证与完成沿用已有契约和回执入口；模块声明及蓝图显示不赋予执行权限，也不决定任务完成。

下列链接保留已有决策、阶段需求和交付记录的阅读路径；正文及生命周期由原 Note 负责。历史 parent 仅组织文档，跨模块关联由本声明的 related-to 补充。模块声明只在职责、接口、明确依赖或代码入口变化时维护。

## Design

旧 HarnessRunPanel 桌面任务执行界面、TaskContractEditor、实现历史面板和无消费者的 harness store 已移除，E2E 不再通过夹具重新挂载退出界面。任务运行／验证／接管后端、共享契约、现用 Chat 和 WorkflowX 监视能力保留；本次清理不声明后端执行能力退出。

通用工程工具、MCP、Note 编辑、压缩和 WorkflowX 模式由 agentX 提供，Janus 负责模型与会话端口、审批界面、子会话事件归属及产品扩展。项目会话从共享工具清单继承工程能力；受限维护讨论继续使用调用者的工具限制。具体分工见 [agentX 复用边界](../blueprint/agentx-harness-inheritance.md)。

内置 Agent 已通过宿主工具调用显式授权的插件公开服务，复用任务预算、执行审批和取消，不注入第三方 Agent JS；当前会话必须匹配选中项目／worktree。契约、代表状态提供者与外部 CLI 未支持矩阵归[插件公开服务](../workbench/plugin-contract-v1.md#p6-首片内置-agent-调用公开服务)，声明式任务已支持宿主默认模型的受限文本生成，UI 与 Agent 共用公开服务且分别拥有结果；模型预算与限制归[模型代发契约](../workbench/plugin-contract-v1.md#p6-受限文本模型代发)，已增加 plugin.skills／plugin.read-skill 两个 inspect 工具，按授权和精确修订返回不可信指引，不自动执行服务；限制归[技能资源契约](../workbench/plugin-contract-v1.md#p6-插件技能资源)。plugin.workflows／plugin.run-workflow 已支持发现精确修订并按宿主审批执行顺序服务，固定直接提供者、共享取消／预算和结果归属，逐步状态归[工作流契约](../workbench/plugin-contract-v1.md#p6-顺序服务工作流)。plugin.contexts／plugin.read-context 已按精确授权返回当前项目已保存文件的文本与哈希，plan 可只读，撤销／取消拒绝迟到结果；项目页面通过 SDK 使用同一资源。边界归[文档上下文契约](../workbench/plugin-contract-v1.md#p6-文档上下文提供者)，P6 按 Windows 声明式代表范围交付。

Janus 模型端口与两个对话入口共用上下文、最大输出额度检测；完整自动资料优先，缺少资料时先更新目录，再支持双额度手动回退。缓存、匹配、生成预算及验证边界由[模型目录决策](model-registry.md)维护。

SuperAgent P1 已提供独立工作记录和宿主输入接口：共享类型、schema、原文持久化、串行记录存储、工作区解析与 IPC 分层。输入先保存再回执，事件去重、工作关联及投递分别记录；退出排空写入，重开读取历史不启动执行。存储边界归[实施计划的 P1 交付记录](./ideas/janus-superagent-mvp-plan.md#p1-交付记录2026-11-06)。P3 已接入受管 Worker、MCP 和必要聊天交互；P4 已将同一 Janus 的正常对话接到工作分派、全局可配置容量和有序队列，后续 P5–P7 的完整上下文、生命周期与侧栏也已落地，分别由下方专题维护。

P2 已增加持久工作环境与具体 Git 操作批准、执行前身份／占用复核和短期执行 lease。创建使用固定基线的隔离目录，删除保留分支；原生权限工厂将 Worker 写入限制到分配目录并保护 Git 元数据，本机 Codex MXC 真实检查通过。模块与存储、旧手动 API 兼容、权限限制及 117 项综合回归见[环境决策](superagent-environments.md)。P3 已把策略和 lease 接入实际 Worker 的启动／恢复／追加／停止，并增加具体快照批准后的宿主提交。

P3 的[Worker 决策](superagent-workers.md)维护受管 stdio 传输、原生线程／轮次身份、持久输入投递、MCP 汇报／读取、外部工具限制及确认停止。现有 JanusChat 已有明确工作绑定、原生审批／问题、补充和报告入口，真实 Codex 与完整 Electron 通路通过；原终端模式继续保留。正常轮次结束不代表 ready，未知投递不重发，未确认停止不释放占用。实例按身份管理，P4 已接入统一可配置容量，默认 2，不固定两个槽位。

循环主干：[loop-refactor](./agent-loop-refactor.md)、[chat-alignment](./janus-agent-chat-alignment.md)、[roundtable-loop](./roundtable-chat-harness-loop.md)、[turn-guard](./chat-turn-guard-domain-s6.md)、[loop-sanitize](./chat-system-mid-conversation.md)、[feedback-parity](./janus-chat-feedback-parity.md)；切除对[removal-plan](./history/legacy-loop-removal-plan.md)与[removal-执行](./legacy-loop-removal.md)成对保留，前者为后者的 cut-list 依据。

## Planned direction

Janus SuperAgent 就是 Janus，保留软件全局控制与唯一对话入口，用户无需选择事项。首版使用 Codex，Worker 调度按可配置容量设计，默认并发数为 2，后续可通过配置增加数量；补充立即转发，叫停立即请求停止。Janus 管理 worktree 并安排 Worker，优先复用工作环境，新建 worktree、合并分支、删除 worktree 均经用户同意后执行；依赖问题与用户确认。完成后汇报 ready，用户自行查看并继续对话，不新增专门验收机制。ready 且执行收尾后空闲 30 分钟回收实例，运行中、等待审批／回答或有待处理活动时不回收；保留目录、分支、记录和代码。收起面板只影响视图，关闭工作停止该工作，明确“停止全部”是全局操作；退出软件保存记录并停止受管执行，重开不自动续跑，也不把所有工作永久关闭。P5 已实现 Inline／Spill、共享工作卡和原文召回，机制与证据见[上下文决策](superagent-context.md)。P6 已接入实例回收、明确继续、停止全部与应用恢复；未确认停止跨重启保留容量和环境占用，机制与边界见[生命周期决策](superagent-lifecycle.md)。范围与条款见[需求](./requirements/janus-superagent.md)，参考、决策和历史原型差异见[架构思路与计划](./ideas/janus-superagent.md)。

P4 已接入两级处理：宿主先保存输入、固定发送时的工作区、按事件身份去重并处理明确控制；同一个 Janus 使用可搜索／分页目录和简单工作卡判断回答、软件操作、新工作、补充／继续、停止、关闭／重开或澄清。派发工具返回安排，不等待开发结束。统一容量 `maxConcurrentWorkers` 默认 2，支持任意正整数 N；满额排队，原工作补充与停止直接处理，原生等待仍占名额，确认退出后释放。历史询问不启动执行，旧决定与迟到回调不能复活关闭工作或释放新执行名额。正式报告仅送入所属对话一次，普通输出刷新视图，不触发自循环模型调用。实现、取舍和验证归[分派与调度决策](superagent-scheduling.md)。

P7 已把同一 Janus 对话接入全局工具分屏，初始界面／Island／工具箱共用启动入口。右侧 Worker 可收起和调宽，窄窗在本 pane 内切换列表；用户仍可唤出并使用项目终端。原生审批、选项和具体 Git 计划在聊天中回答，状态卡只显示真实实例与安排。启动后 Island 手势仅通知，明确定位才导航。实现取舍归[界面决策](superagent-interface.md)。2026-11-06 用户明确本轮不以 HTML 为设计参考或交付要求；多引擎仍后置。P8 联合检查及未完成范围归[验收证据](superagent-verification.md)。

外部 Worker 的 MCP 已在 P3 提供 `report_work`、`read_work`、`read_resource` 和受控 `commit_work`，由宿主凭据绑定工作／执行并先保存再回执；原始材料超大时分页。P5 已补齐完整工作卡、链式召回和模型上下文保护，具体执行边界归[Worker 决策](superagent-workers.md)。

P5 已实现工作目录、工作卡和原始材料三层结构：程序维护事实，Janus 理解目标／约束，Worker 汇报结果；新输入立即保存转发，旧摘要未覆盖部分从原文补齐。用户要求参考 DSH 的直接投影、预览引用、分页及投递／纳入区分，证据与简化建议归设计 Note。目录包含回收／关闭工作的历史，外部 Worker 通过 MCP 按需读取，不另设记忆 Agent；具体 schema、来源覆盖、版本分页与模型读取保护由[上下文决策](superagent-context.md)维护。
