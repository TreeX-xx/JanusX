# Agent 对话与执行

## Responsibility

JanusX 将普通对话、工具调用、Task 执行和可选的 SuperAgent 编排接入共享 Agent 引擎。宿主负责模型与会话端口、审批、工作区归属、受管进程及用户界面。工程工具、上下文和调度的共享实现随仓库固定的引擎包交付。

## Design

普通对话按项目或工作区关联会话。模型额度及回退见[模型目录](model-registry.md)，事件、工具与输出在[工作时间线](requirements/chat-work-timeline.md)中呈现。备忘录与运行配置工具由引擎实现，并通过宿主端口访问持久化和进程服务。各文件的迁移去向见[工具迁移清单](../../../docs/migrations/agent-tools-engine.json)。

普通 xdo 可直接使用工程工具。绑定 Task 时由 Main 维护文档，执行按固定范围、AC 和评审约定留存证据。线程可在运行结束后继续保留；桌面仍提供运行、验证、接管和[线程后端](../sessions/threads/thread-registry-activation.md)。旧独立执行面板和[蓝图维护循环](legacy-loop-removal.md)已退役。接入历史见[WorkflowX v2](../blueprint/workflowx-v2-adoption.md)。

SuperAgent 的输入先持久化，工作绑定具体工作区与执行身份；[调度器](superagent-scheduling.md)控制容量、排队和恢复，[环境](superagent-environments.md)承载工作目录、批准与 Git 操作，[Worker](superagent-workers.md)维护原生线程、投递、汇报及停止语义。普通聊天和编排入口分别检查能力；当前宿主、官方实验插件和引擎的分工见[插件迁移](superagent-plugin-migration.md)，平台与真实模型验证见[验证记录](superagent-verification.md)。

## Planned direction

[插件决策](superagent-plugin.md)定义可选编排的安装边界。[MVP 计划](ideas/janus-superagent-mvp-plan.md)和[上下文优化](ideas/superagent-context-simplification.md)保存分阶段设计，当前行为按各专题和实际运行能力核对。
