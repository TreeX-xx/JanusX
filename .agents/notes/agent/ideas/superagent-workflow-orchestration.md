# SuperAgent 多 Worker 任务编排

## Problem

用户希望用自然语言描述一个目标与分工，生成多个角色的 Worker，例如一个开发、一个测试，或前后端并行后进入验收。2026-11-12 在审阅离线 HTML 后明确以 xdo 授权生产 UI 与编排实现。现有三级优先级保持不变。

现有工作项与 Worker 之上增加父流程。角色与引擎分开，未指定引擎时遵守默认值及允许列表。相同 Janus 通过 work_plan 提出 2–8 个节点的无环依赖图，宿主校验并写入 workflows.json；稳定的原始输入与计划 key 去重，内容冲突拒绝替换。每个节点保持普通 Work 身份，依赖就绪后才进入既有全局队列，父流程和依赖等待均不占执行名额。

右侧采用父任务分组，编排节点与独立 Worker 共用两行卡片：任务标题、角色／引擎和状态。整体阶段在组标题显示，全局占用保留在侧栏标题；完成步骤、返修次数与交接规则收进「流程详情」，执行记录和操作随 Worker 卡片展开。依赖等待、容量排队、运行、暂停和失败分别表达；暂停后续允许当前步骤完成，停止父任务只作用于自己的子节点。节点直投保留依赖和排队，测试交接核对目录版本，发现漂移时不能将原结果作为稳定交付。

## Prototype

入口为 [design/superagent-bubbles/SuperAgent Bubbles.html](../../../../design/superagent-bubbles/SuperAgent%20Bubbles.html)，保留原对话与 Worker 场景，默认展示开发→独立测试→Janus 汇总。另提供前后端并行汇合、跨任务名额等待、测试返修场景。生产实现采用演示的一轮默认返修上限，实际执行规则见下文。

可点击推进、暂停／恢复、停止确认、角色详情、@角色补充及自然语言样例。样例通过本地规则选择预设计划，所有版本、测试结果与 Worker 动态均为模拟；没有接入真实调度、引擎或新权限。

本轮简化卡片后，10 组编排与共用样式检查、22 组原有交互检查通过，运行错误和外部请求为0。已查看编排与独立 Worker 同屏、原有独立卡片、深浅主题和窄屏截图。记录位于 `artifacts/orchestration-compact-preview/`，复现命令与源码入口见[原型 README](../../../../design/superagent-bubbles/README.md)。

## Decision

流程状态为准备、进行、暂停、待处理、完成、停止中、已停止与待恢复；节点分别记录依赖等待、准备、排队、执行、交付、待处理与停止。ready 报告必须对应当前原生执行、派发版本与已投递输入，且进程确认结束，才能推进依赖。旧报告不会自动交付新任务。全部节点交付后由宿主聚合状态和报告历史；这表示 Worker 的交付声明，不把结构校验当作独立正确性证明，也不增加总结模型回合。

测试节点接收依赖的完整原始报告，并使用实际交付目录。开始排队、实际启动和接受测试结果时核对 HEAD、受版本控制及未忽略文件的 SHA-256 指纹。检测到变化便转为待处理；多个依赖位于不同目录时，必须先明确集成。该机制检测版本漂移，不是隔离快照，也不能证明执行期间从未发生又被还原的修改。测试被要求不改业务源码；验证产物应放忽略目录或执行 scratch。扫描上限为 10 万文件、1 GiB，超限明确阻塞。需要大型仓库或互相重叠的并行验证时，应重新评估独立交付快照，而非放宽核对。

测试 failure 默认最多自动返修一轮，可在计划中设为零；开发祖先及其后续节点重新入队，失败原文作为本轮交接。第二次失败、没有开发依赖、其他节点仍运行或关键证据缺失时转为待处理。暂停阻止后续启动，当前执行可以完成；恢复保留原排队顺序并更新暂停期间的追加输入。停止父流程取消自己的未完成节点并等待原生结束，stop-all 同时停止父流程，避免残留依赖后来启动。单独停止或取消未完成子节点，先将父流程置为待处理；其他已运行节点可完成，但被停止节点不能在依赖完成后自行复活，必须明确恢复父流程。

重启后未结束流程只恢复为 interrupted，不自动消费旧指令。明确恢复会记录新授权输入，确认旧执行停止后重新安排未交付节点；已交付节点保留。流程定义不能原位改写，已结束节点的额外工作需新计划。@ 对未开始节点保存补充，但启动入口、队列恢复与原生续投均不能绕过依赖和父流程状态。引擎允许列表仍在创建及实际启动时执行，原有 Git／原生审批保持不变。

核心实现位于 janus-agentX 的 superagent/workflows.ts、workflow-store.ts 与 workflow-checkpoint.ts；桌面通过固定包接入。UI、IPC、默认引擎及快捷指令适配留在 JanusX。生产验证与构建身份见[验收记录](../superagent-verification.md)，原型中的模拟推进按钮不是生产接口。

## Alternatives considered

直接创建多个独立 Work 可以复用执行器，但无法表达测试依赖、父级暂停和有限返修，因此保留为独立任务入口。让额外协调模型轮询每个阶段会增加延迟与不确定重试；本次采用宿主依赖图推进，仅由当前 Janus 解释初始分工。为每次测试强制提交并复制独立快照能够加强隔离，却会改变已有共享工作目录与 Git 审批流程，本次采用只读版本指纹并明确其局限。

## Consequences

节点沿用普通 Work 的审批、上下文、队列和报告，独立卡片与编排子卡片因此共用实现。代价是新增一份严格版本化的流程记录，以及交接前后的文件扫描；不同目录的并行成果仍需要明确集成。完成状态只汇总当前交付证据，不替代测试真实性或用户验收。大型仓库、频繁共享目录漂移或动态改写流程成为常见需求时，应重新评估快照与计划修订协议，而非静默跳过检查。
