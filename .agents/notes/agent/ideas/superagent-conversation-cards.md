# SuperAgent 多输入对话卡片

## Intent

用户希望 Janus 分析期间仍可连续输入并临时并行。2026-11-11 明确要求连续输入像 Codex CLI 一样参与当前思考和输出，改为单个活动回合默认立即补充。2026-11-12 输入83进一步移除“独立提问”界面入口，公共输入仍走普通提交路径；既有并行历史和内部调度能力保留。并行两支共享同一历史节点，结束后完整问答汇入后续普通对话。此决定替代早期“每条输入先成卡、相关输入排队”的方案，当前事实归[界面决策](../superagent-interface.md)。下文原型探索历史不再约束现行输入流程。

SuperAgent 主体只读取、分析和协调，不允许修改文件；真正的编辑交给已有 Worker。多个对话卡片可同时分析，不需要因为主 Agent 文件写入而互斥。对同一 Work 的协调动作仍需 revision 检查、去重与顺序控制，不因只读分析而删除现有 Worker 调度和环境隔离。

## 运行中补充即时生效（2026-11-11）

用户在分析后明确授权实施 Codex CLI 式体验。原瓶颈在桌面 TopicScheduler：相关输入标为 queued，pump 跳过活动会话；归属判断及 afterGroup 又增加等待。现已接入底层已有的 AgentSteeringPort，单活动回合直接投递，输入保持原身份并绑定活动 requestId。另修复 agent-core 在上下文准备／压缩期间尚未挂抢占钩子的间隙，建流前重新消费并生成上下文。

保留通用模型适配的本地流式抢占：生成时中止独立 attempt signal，保留已输出正文，纳入补充后继续同一回合；工具执行时在安全边界消费并保持调用／结果配对。消费回执确认纳入上下文，不等于模型已遵从。Worker 的 Codex 适配已有 turn/steer；主 Janus 收到补充后仍需通过现有 Work 路由下达相关要求。

选择默认直接补充，是为了消除单会话归属模型的额外延迟；当时的“独立提问”按钮已按输入83移除。多分支目标仍可能需要模型归属判断。结果不明不自动重放，完整状态、失败与恢复规则归[界面决策](../superagent-interface.md)，当前测试与固定六包证据归[验收记录](../superagent-verification.md)。

## 实施前基础（2026-11-09）

`useJanusChat.ts` 在运行中收到消息会直接走 steering；`chat-orchestrator.ts` 对同一 conversationId 只允许一个活动回合，不同 conversationId 可以并行，`chat-turn-guard.test.ts` 已有对应测试。前端 runtimeStates 和 handles 已按会话隔离，SuperAgentWorkspace 当前只展示一个控制器。后端 SuperAgent 已迁至固定版本 agentX 包，桌面兼容入口只是转导出。

当前 steering 会抢占模型流或在工具间隙应用。本提案改变普通补充的处理方式：相关输入合并后等待前一个回合完成，不立即打断当前回答。显式停止仍应走控制通道，不能排在待停止任务之后。这与 Worker 收到已确定补充后的投递策略属于不同层次，不将原有“立即转发给 Worker”条款误写为全局排队。

## 输入、路由与上下文

1. 每次发送先持久化唯一 inputId，立刻生成包含用户原文的临时卡片，显示“判断归属”。判断尚未结束也允许继续输入。
2. 独立于正在运行回合的轻量路由读取公共上下文和活跃／近期卡片目标，依据目标与依赖判断归属，不只按相邻文本或主题词。连续到达的路由决策按输入序号提交，避免两个相关新输入同时误建独立分支；分析执行仍可并行。
3. 相关输入将临时卡片合入目标卡片；原文及身份保留，显示合并回执和排队位置。每卡片最多一个回合运行，队列按序推进，每项都有自己的回答，卡内构成完整对话流。
4. 无关输入保留独立卡片，创建独立会话／请求／取消句柄，与其他卡片并行。新卡片不等于新 Work，也不自动启动 Worker。相关但依赖前项结果的输入排队；跨卡片依赖显式等待，不能把缺失结果当已知。
5. 公共历史按分叉位置固定快照，继承已完成对话、项目资源、模型与工具权限机制；各分支独立追加记录、工具结果和压缩 checkpoint。尚在生成的其他分支输出不混入历史。完成结果由明确引用或跨卡片汇总进入后续上下文，不按到达顺序拼接。
6. agentX 输入账本保留 parentThreadId、baseContextRef 和原始输入来源等必要关联（字段名为建议）。复制历史不重新授权旧指令；路由提交时复核目标状态。输入投递幂等，结束、关闭与迟到事件不导致重放或复活。

置信不足时卡片保留待确认状态并请求归属，不静默猜测执行目标。原型以明确标注的本地规则演示已知样例，不能作为语义判断准确性的证明。

## 展示与 Worker 交互

主区保留统一输入框，卡片内部包含用户消息、读取活动、回答和待处理队列。卡片可收起，后台处理不受可见性影响；不同卡片各自流式更新，不把输出交错写到同一消息。合并给予短暂可见反馈，不吞掉刚发送的输入。普通点击、展开和查看 Worker 不改变公共输入的归属。

单次提问也保留同一话题结构，但单卡淡化边框、编号和统计；没有等待项不显示队列，阅读使用主区滚动，避免短对话内再套滚动条。卡片代表话题，而非一条输入。已完成后相关追问合并并直接续答；首条输入没有候选时直接开始，不人为等待归属判断。多个话题才强化卡片边界与并行状态，完成卡片可手动收起成结论摘要，不自动收起用户正在阅读的内容。

合并过渡采用“先告知去向、再收拢、目标渐入”的顺序，避免临时卡片突然消失：归属确认后源卡片标题直接显示目标话题，目标卡片提示有相关补充；原型停留约 950 ms，再用约 700 ms 同步收拢高度、间距和透明度，目标新增消息渐入，周边卡片随布局平滑移动。合并回执保留 6.5 秒，提供“查看此话题”；不会强制展开目标或抢走输入焦点。连续发送和重绘沿原时间轴继续，不重启动画；重置清除待合并状态。减少动态效果偏好保留去向说明但省略移动动画。时间参数为原型审阅值，不作为生产调度必须等待动画的要求。

右侧 Worker 卡片首先展示实际终端／引擎类型，再展示当前执行的工作与最新状态，之后才提供展开和关闭。收起时持续订阅运行状态，异常摘要和错误内容照常加载；展开仅影响详细日志的呈现，不是错误发现或状态更新的前提。失败停止运行指示，不出现永久加载假象。

关闭沿用已有语义：请求停止该工作，先显示“正在关闭”，确认停止后标记关闭并保留记录；不是仅折叠，也不是自动删除代码或 worktree。错误重试需明确动作，不因展开或收起自动重试。演示中的不同终端类型只说明呈现方式，不表示多引擎后端已经实现。

第二版将终端类型与实例标识放在卡片头部，状态靠右，当前工作与最新动态构成主体。展开记录和关闭工作放在次级操作区；失败时错误区突出原因、保留情况与重试连接，错误详情独立于正常日志。原型增加行内关闭确认与取消，确认后仍等待停止回执，属于供用户审阅的交互设计。

Janus 提问在所属对话流内提供单选、选项说明、建议标记和自定义文本；不默认替用户选答案，空自定义内容不能提交。稍后回答保留选择和草稿，只暂停所属话题；提交显示发送中并防止重复，成功后留下来源与回答回执。Worker 等待时在右侧显示问题摘要，回答入口定位到包含来源的对话卡片，结果只交回对应 Worker。主区回答中断保留部分内容，提供原因与同卡重试；与右侧 Worker 连接错误分开展示。
