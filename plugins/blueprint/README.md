# Blueprint official plugin

Source is maintained here, with UI in `src/ui`, business services and the independent Note MCP in `src/main`, and internal DTOs in `src/shared`. The host owns installation, signatures, consent, isolated pages and native process supervision. The plugin reuses the public SDK and shared Janus Agent/Note packages; it must not import host `src` modules.

Blueprint uses the original full-screen floating card layout: it covers the main titlebar and keeps one close/project header, one compact toolbar, a left reader, a central canvas and an optional right Janus card. The plugin owns the original first row (project, updates, suggestions, optional review activity, Janus and close) through the public `views.workbench.frame` contract. The second row holds search, status/type filters and canvas controls; Settings, refresh and navigation history are in More. Source diagnostics and attention lists use popovers without moving the canvas. Initial reads show the original loading card and reader shimmer skeleton. Cards enter 180ms apart over 260ms, nodes use the original capped CSS stagger, and close reverses the cards at 60ms intervals. Reduced-motion preferences suppress these animations. Reader and discussion headers stay fixed; their content scrolls separately, with the discussion composer at the bottom. The toolbox has one Blueprint command. Its Settings shortcut opens the same settings-center page. Discussion starts closed and remains mounted when hidden. If Island is expanded through a host action, the workbench temporarily hides without clearing its state; the covered main Island is not a second visible chat entry. Graph loading uses an immutable, owner-bound snapshot split into bounded native responses; refreshed graph DTOs retain measured node sizes so settings round trips do not leave cards hidden. The center restores the original 24px dotted grid, theme colors, zoom range, module browser, bottom legend, empty-module hint and node context menu. Module views omit stock zoom controls and minimaps; legacy graphs retain a minimap up to 250 nodes. Opening or closing side cards refits the available canvas after its dimensions settle, while same-module selection preserves the next wheel gesture and history navigation restores its saved viewport. The reader now uses the original Wiki toolbar, collapsed review card, chapter directory/folding, relation previews and collapsed provenance. Update/suggestion panels use the original search, module filter, scrollable rows, previous/next controls and filtered read/undo actions. Loading diagnostics stay in the toolbar rather than a separate bottom row. The existing notes.read derives its Markdown view on the backend from the same fresh body; no host-private browser code or new file permission is used. The source menu provides raw/preview and version-checked opening. Direct clipboard writing, external links/images and host chat rendering retain plugin limitations; raw text can be selected and copied manually.

From the repository root, run `npm run plugins:blueprint:verify`. It packs the declared public dependencies using npm's publication rules, verifies their pinned archive hashes, copies only plugin sources into a new temporary directory, installs with `npm ci --ignore-scripts`, checks types and builds the browser/native entries. The receipt is `artifacts/plugins/blueprint-build.json`; its `project` directory contains the complete independent source, dependency archives and output. No `node_modules` files are patched.

Run `npm run plugins:blueprint:check` for the complete local gate: it performs that independent build, then signs and installs its exact output into an isolated Electron profile. The UI regression covers settings conflicts and drafts, read acknowledgement, review, streamed discussion, dispatch handoff, confirmed writes without audit history, process shutdown, and configuration recovery after uninstall/reinstall. Runtime status and output hashes are recorded in the same receipt. `verify` and the Windows PR workflow invoke this gate and the distribution checks; CI uploads the receipts. `npm run test:blueprint:desktop` runs just the carrier test, using `JANUS_BLUEPRINT_PACKAGE` when set and a local build otherwise. It needs no island Vite server.

The package uses explicit npm overrides for shared packages that still declare sibling `file:` dependencies. All such references resolve to the same pinned archives in `vendor/`. After reviewing a dependency change, use `npm run plugins:blueprint:verify -- --update-lock` to regenerate both `build-dependencies.lock.json` and `package-lock.json`. Normal builds reject differing dependency bytes, even when the version number is unchanged.

To use the plugin yourself, run `npm run dev:blueprint` from the repository root. No Release upload is required. It builds and signs a local package, opens the full desktop with a separate profile, and installs Blueprint disabled. Add a project, then open Settings → Plugins → Installed, review permissions, select that project and enable Blueprint. Open Blueprint from the toolbox; configure your own model in this test profile when testing review or discussion. Reading existing Notes needs no model. Settings save automatically; a conflict retains your input and stops further submissions until you reload.

The persistent test profile is `.cache/blueprint-local/profile`; knowledge data is isolated beneath it. The local signing identity, public trust and versioned package copies stay under `.cache/blueprint-local` and are ignored by Git. Local trust is compiled only into this development build, and the normal production trust file is unchanged. Stop the session and rerun `npm run dev:blueprint` after changing plugin code: each run adds an increasing `-local.N` suffix to the manifest version and retains data, but an updated package needs explicit enablement again. `npm run dev:blueprint -- --prepare-only` builds and signs without opening Electron.

`npm run test:blueprint:local` builds a separate full desktop in a temporary cache directory with a copy of the repository Notes corpus. It verifies installation, explicit permission consent, automatic settings persistence, real graph/Note reading, full-screen titlebar coverage, toolbar/card geometry, source popovers and the shared settings shortcut with visible nodes after returning. It then closes the desktop and reads its root Note through the generated standalone MCP launcher. It uses no model. The signed carrier test remains `npm run test:blueprint:desktop`; its model responses are deterministic fixtures. Neither test validates production model quality or a public catalog.

For fast local iteration, `npm run typecheck --prefix plugins/blueprint` and `npm run build --prefix plugins/blueprint` can resolve the repository's installed public packages. These commands alone do not prove build independence. Native plugins still require a verified signed package; unsigned development directory activation is unavailable.

Users import one `.jxp` file in Settings → Plugins → Installed → Import plugin package, then review permissions, select projects and enable it. The self-contained `jxp/2` container embeds its signed release description and compressed payload; no separate JSON, extraction, development mode, network request or Release upload is needed for local installation. The host must already trust the signing public key and allow it for Blueprint native services; the 2026-10-26 delivery host pins `janusx-blueprint-20261026` for Blueprint. Updating requires disabling the installed plugin first. A companion `.release.json` is still generated for catalog publishing tools, but users do not need it. Existing raw packages remain supported by the online installer with their signed catalog entry; local import requires the new self-contained format and an updated host. Ordinary ZIP files are not plugin packages.

Use Import legacy Blueprint in the workbench toolbar to convert the JSON copies preserved under the plugin's `legacy/` directory into Notes in the selected project. Read the preview, then confirm its exact identities and content. The preview expires after ten minutes and is bound to that page, project and source version. Conversion writes draft Notes and a report in one shared transaction, then archives the plugin copy; original application data remains intact. Historical task checklists become ordinary Notes under harness-note/2 and never execute automatically. A persisted conversion marker blocks duplicate import after an interrupted archive; inspect the project and archive when recovery is required.

Distribution includes only `manifest.json` and `dist/`. Run the repository's package/sign/catalog tools against the verified independent output. `release.json` names the intended separate `JanusX-plugins` release source; that source is not deployed; the 2026-10-26 local delivery signing public key is pinned in host trust. Shared authoring and workspace initialization now come from the ninth public archive, `@janusx/note-tools`. The original eight archives remain byte-identical. Version 1.0.1 keeps the original 1.0.0 delivery immutable. Source cleanup is complete for the three checked host entries; the complete compatibility matrix remains open.

After building the Windows setup and portable artifacts, run `node scripts/check-packaged-runtime.mjs --portable --release-dir RELEASE_DIR` to check the archive, repository-external module loading, visible GUI and portable launcher. Then run `node scripts/plugins/check-blueprint-packaged.mjs RELEASE_DIR PACKAGE [BASELINE_DIR]` against the signed package. It uses fresh profiles and executable copies outside the repository, checks absent/disabled/enabled states and process shutdown, preserves the copied Notes, and records three alternating startup samples when a frozen baseline is supplied. Its receipts and screenshots stay under `RELEASE_DIR/verification`. First root content is a startup proxy; OS file caches are not flushed and memory sums are not exclusive physical memory.

With a prior delivery directory supplied, append `--compatibility` for a separate installation/version check. It reinstalls the original package, upgrades to the candidate and rolls back, checking persisted settings and unchanged root Note content. It skips the startup comparison and writes under `verification/compatibility`; it does not establish compatibility with every historical schema or host version.

The host packaging configuration excludes the complete `plugins/` tree. Its archive/runtime check also rejects plugin payloads in asar, smart-unpacked files and sidecar locations. Dependency gates require zero Blueprint business inputs in main, renderer and remote workspace entries; old host calls return `BLUEPRINT_PLUGIN_REQUIRED`. Generic Note operations, roundtables, chat change cards and confirmation dialogs retain their shared implementations. The UI schedules its SDK requests below the host's unchanged page limits, with bounded concurrency and cancellation before dispatch. Index and coverage-proof reads wait briefly for another process's Notes lock; submitted writes are never automatically replayed. Version 1.0.3 applies the exact confirmed preview through the Note transaction and completes without a Blueprint audit file or a post-commit graph snapshot. The UI refreshes independently. Maintenance audit/undo methods and the history panel are removed; existing private data and the shared engine's transaction journal are retained. Legacy application upgrades and maintenance undo are outside the current delivery scope.
